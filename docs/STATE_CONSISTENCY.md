# 第二阶段：跨项目状态与版本对比可靠性

验证日期：2026-09-12。本轮沿用现有菜单和绿色 Terminal 风格，没有新增产品模块、升级依赖、调用在线模型或推送 GitHub。

## 1. 本轮解决的问题

| 场景 | 原有风险 | 本轮处理 |
| --- | --- | --- |
| 从项目 A 快速切换到 B | A 的延迟错误或报告覆盖 B 的界面 | 项目选择、报告和列表请求分别检查请求序号；旧成功、错误和结束状态均不能写入新请求状态 |
| A 的搜索未结束就切换项目 | B 仍显示搜索中，不能立即搜索 | 切换时失效旧搜索并重置加载状态；B 可以独立发起查询 |
| 对比请求中更换基线或目标 | 显示上一组版本的结果，却保留新筛选值 | 校验项目、基线和目标的组合；更换选择后清除旧结果并忽略过期响应 |
| 离开版本对比页时远程同步尚未结束 | 已卸载页面继续轮询或修改界面 | 停止该页面后续轮询与状态写入；服务端已提交的任务继续运行，不视为取消同步 |
| 缓存失效时旧计算尚未完成 | 旧计算重新填入缓存，后续请求读到旧分析 | 缓存条目身份作为代际标记；失效、清空和淘汰后，旧计算不能再次发布缓存 |
| 分析提交过程中有请求建立旧缓存 | 即使开始分析时清过缓存，提交后仍可能遗留旧结果 | 全量分析、实际发生变更的增量分析、同步替换和删除在提交后再次失效缓存 |
| 后台分析或同步过程中删除项目 | 正在使用的项目数据和源码被删除 | 对已登记的 queued/running 后台任务及 analyzing 状态返回 409；前端明确提示等待任务结束 |
| 评分规则或解析器变化后比较快照 | 将分析方法变化显示成质量提升或已修复 | 保存分析口径；不同或未知口径时保留观测值，暂停算法相关差值与修复判断 |

缓存仍为每个数据库最多 16 个项目的进程内缓存。代际校验不保存无限增长的历史标记，也不会把耗时计算放进全局锁。失效前发起的调用可能完成并收到原计算结果，但该结果不能供后续请求缓存命中。

## 2. 快照如何保证可解释性

新快照使用 payload version 2，随结果保存 `analysis_context`，包括：

- 评分模型标识及规则参数摘要；
- 解析逻辑版本、已安装语法包版本和支持扩展名的摘要；
- 可评分源码数、支持结构解析的文件数、解析覆盖比例、适用规则数及解析问题文件数。

这些是内部比较依据，不在页面上罗列权重或参考变量。“解析覆盖”表示静态分析适用范围，不是运行时测试覆盖率，也不能证明业务行为正确。

保存快照不等于重新解析。手动快照沿用最近一次实际分析的解析器来源；找不到来源时标为未知。增量分析会保留未变文件的结构：如果之前的解析器未知或与当前不同，也不能将整份索引标记为新解析器产物。此时需要用户执行现有的全量分析，重新建立一致来源。

解析器或导入解析语义改变时，维护者应同步更新 `backend/app/services/code_parser.py` 的 `PARSER_ANALYSIS_VERSION`。评分公式改变时应更新评分模型标识；阈值和权重变化还会被参数摘要捕获。

### 比较行为

同口径快照保留原有差值与问题对比。评分模型、规则摘要、解析器或覆盖情况不同，以及任何一侧缺少口径信息时：

- 提示差异不能直接归因于代码修改；
- 综合分、符号、依赖、问题等算法相关指标返回 `delta: null`，页面显示“不计差值”；文件数量仍可比较；
- 问题分组改为“新增检出 / 不再检出 / 两次检出”，不把“不再检出”直接标成“已修复”；
- API 返回 `comparable` 和 `comparison_warnings`。集合差分中的 `fixed_count` 为兼容保留，调用方必须结合 `comparable` 解释，不能单独当作已验证修复数量。

历史快照继续可读，不补造旧版本信息，也不重写旧记录。新前端遇到尚未提供口径字段的旧后端时，同样按未知口径展示。

## 4. 仍然存在的边界与下一步

- 这是本地单实例下的可靠性加固，不是分布式事务或跨进程互斥锁。后台任务登记检查不是原子删除锁；同步提交、另一个新任务和直接调用同步分析接口之间的所有竞争尚未穷举。
- 过期请求主要通过忽略响应隔离；并非所有 HTTP 请求都主动取消，也不会取消已经提交的分析任务。
- 问题按规则、路径和位置匹配，移动代码可能产生新增/消失项。同口径下“已修复”仍是静态问题集合的判断，不等于真实测试通过。
- 测试仍有 SQLite 连接释放警告及第三方 TestClient 弃用警告，未通过屏蔽警告处理。
- 第一阶段的 36 道合成问答检索回归继续通过，但未调用真实生成模型，不能由此宣称问答回答准确率达到 100%。

第三阶段建议先做现有页面的小、中、大仓库性能基准，再逐页拆分 `App.tsx`、统一请求取消和样式维护。新增菜单、分析能力或其他产品功能仍须先向用户确认。

## 5. 后续打磨：耦合分析与源码查看

更新日期：2026-09-12。按用户要求暂停真实生成 API 验收，仅完善已有功能。本节是后续验证记录；第 3 节数字保留为当时基线。

### 已修复

- **对象搜索先排序再截断**：原先 SQL 先无序 LIMIT，再在内存排序，大量模糊候选会挤掉精确名称。现在先按简单名、限定名或路径的精确/前缀匹配排序，再有界取候选；显示仍保留限定名称。`_`、`%` 按输入字面搜索，不再意外成为 SQL 通配符。
- **长函数的依赖候选**：原先要求单个索引片段完整包含函数，但每个片段最多 80 行，长函数因此漏掉被调用对象。现在读取与目标区间相交的片段、裁剪相邻源码、合并标识符；大于读取上限时保留首尾片段。
- **耦合页面请求隔离**：提取已有 `ImpactWorkspace` 组件，复用读取取消管理。编辑查询、切换对象、离页均取消旧读取；即使服务器忽略取消，旧成功、失败和结束状态也不能覆盖新操作。新检索或分析清除旧列表/报告；零匹配与首次进入分开展示。
- **菜单往返保留对象**：同项目切换菜单再回耦合页，重新读取最近选中的对象，而不是丢失选择或回到最初从概览传入的对象。记忆的是已选对象，不是尚未提交的搜索草稿。
- **索引更新后清除旧上下文**：全量分析成功、增量分析有实际变化、远程同步完成及导入后，使耦合对象、候选请求与源码查看上下文失效，避免继续使用旧符号 ID。即使分析结束时用户已经返回耦合页且没有选中对象，旧检索也会取消。无变化增量分析不强制丢弃已有对象。
- **源码查看不混用文件**：读取状态绑定项目及文件；加载或失败时不显示、复制上一份源码。切换、关闭、卸载取消读取，并清理复制反馈和计时器。同文件换定位行会重新滚动。耦合页的源码引用优先跳到实际证据行，不再跳到索引片段的开头。

没有新增菜单、恢复全量函数调用图、修改评分权重或调整绿色 Terminal 样式。

### 验证

- 后端：219 项通过，覆盖率 85.80%；相对上一轮新增 16 项耦合分析回归，包含候选截断、方法限定名、字面搜索，以及 4/100/17,000 行函数的首尾覆盖和邻接代码排除。
- 前端：75 项通过；相对上一轮新增 27 项，覆盖旧请求成功/失败、重分析失效、Strict Mode、关闭/重试/复制与同文件定位。

### 手动验收及边界

1. 在代码搜索找到结果，点击“分析影响”；这是文件级入口。要聚焦函数或类，在耦合页搜索并选择相应符号，或从概览的符号列表进入。
2. 点击直接引用对象查看源码，应定位实际引用行。切换菜单后返回耦合页，应恢复最后选中对象。
3. 查找不存在的名称，应显示无匹配提示；快速更改查询或切换项目，旧结果和旧错误不应回填。
4. 完成一次全量分析后重新选择对象。清空旧对象是因为源码索引可能重建，并非分析结果丢失。

关系仍是静态候选，不代表运行时调用图或经执行验证的业务链。每个目标最多读取 240 个片段、选择 80 个标识符并返回至多 24 个关系候选；超大符号中部及动态调用可能未覆盖。“未发现”不能解释成“确定无依赖或无测试”。本轮未重新测量大型仓库端到端性能，也没有生成模型回答质量数据。

下一轮建议继续完善已有文件树与代码搜索的取消、分页和重试一致性，再清理测试数据库连接生命周期。新增产品能力仍须先征求用户确认。

## 6. 后续打磨：文件树与代码搜索

更新日期：2026-09-12。继续完善现有菜单，不新增产品功能、不调用真实生成 API、不推送 GitHub。以下为本轮结果，前述章节保留历史验收数字。

### 使用体验与正确性

- 文件树提取为独立组件，根目录、展开目录、折叠和离页的读取均可取消；晚到的成功、失败不能写入已取消的目录。只有成功的空响应才显示空目录，失败保留重试入口。
- 缓存成功读取的嵌套目录，折叠后再展开不重复读取；折叠会卸载后代节点并取消未完成读取。全量分析、有变化增量分析和同步完成时，目录缓存随索引代际失效。
- 根目录及展开目录每批渲染 200 个直接子项，沿用 Terminal 的加载更多控件。“直接子项”不是后代文件总数；大目录展示数量不再与目录文件数混为一谈。每次重开折叠目录的渲染上限从首批开始，但可复用已读取的数据。
- 查询目录使用大小写精确的前缀匹配，修复 SQLite 的 LIKE 将 `src` 和 `SRC` 混在一起的问题；`_`、`%` 保持字面含义，其他项目数据不混入。
- 搜索复用读取取消管理。修改关键词可立即发起新搜索；离页取消未完成查询或分页，但保留已完成结果，菜单往返可继续阅读。项目切换清空查询，当前项目索引更新保留关键词并失效旧结果。
- 分页的下一位置取自服务端偏移与原始返回行数，不再由去重后的卡片数量推算。下一页失败时保留已加载结果，点击“重试加载”重试原偏移；无进展或不一致的分页给出重新搜索提示，避免按钮静默无效。
- 搜索错误在搜索区域内展示，不再晚到后污染其他菜单；首屏失败与“没有匹配代码”分开展示。
- BM25 为零的片段不再获得固定符号加分而被当成命中。完全不存在的关键词现在正确返回零结果，匹配总数和分页只统计真正的词法命中（含现有概念词扩展）。

### 兼容性处理

严格排除零命中候选后，离线问答固定题 `worker-03` 暴露了旧召回缺口：问题使用接口/route 线索，而源码是 `ROUTES` 和 `routes.py`。旧逻辑偶然靠零命中符号进入候选，新逻辑按 API 意图补充 `routes/endpoints` 复数词。没有撤回搜索过滤、改题库或放宽断言，也没有调用生成模型。36 道合成题仍全部通过。

本轮未复测真实 60 题或语义消融；原真实评测文档已标注其实现时点，不能据此宣称当前生成问答质量。

### 验证及限制

- 后端 227 项通过，覆盖率 85.80%，通过 85% 门槛；新增 8 项搜索和目录服务回归。
- 前端 106 项通过；新增 17 项文件树交互、11 项搜索状态、2 项分析后文件树刷新、1 项读取参数回归。
- Playwright 8 项全部通过，退出码 0。新增浏览器用例验证改词真实触发 `ERR_ABORTED`、下一页失败后原位重试，以及 450 个条目按 200→400→450 展示且不追加目录请求。
- 大目录截图和计算样式确认按钮保留绿色、直角、等宽字体；TypeScript/Vite、Ruff（app/tests/evaluations）及 Markdown 链接检查通过。
- 测试使用 D 盘临时数据与隔离服务；测试服务正常退出，未操作日常 8000/5173 服务。仍有既有 SQLite 连接释放与 TestClient 弃用警告。

这里的 200 项是 **DOM 渐进渲染，不是网络分页**：服务端仍读取目录下文件元数据并返回全部直接子项，网络响应和数据库峰值内存尚未做这一层优化。逐批显示完所有条目后，页面仍可能有大量 DOM，未宣称无限规模下无卡顿。

分页可检测匹配总数或索引片段数改变，本窗口的分析操作也会主动失效结果；其他客户端恰好造成等计数的索引替换，现有协议没有版本游标，仍可能无法识别。请求取消只是客户端停止等待，并不保证后端已启动的计算立即中止。

### 下一推进方向：大仓库读取性能与资源收尾

1. 为**目录读取**补充固定小/中/大样本的首屏、展开目录、响应体和内存基准；此前性能报告不应代替新增文件树流程的实测。
2. 在现有文件树接口内优化目录聚合及后端分页，减少每次展开扫描和返回的数据；继续验证排序、大小写、后代计数与分页边界。属于现有功能深化，无需新增菜单。
3. 清理测试数据库连接生命周期，解决连接释放警告；用重复进入/退出、重分析及失败重试验证连接、请求和内存能回收。

验收应给出同一批样本的前后数据和未覆盖的边界，而不是预设提速比例。若进一步引入索引版本游标、新的持久化目录索引或其他需要扩展产品能力的方案，先说明范围并征求用户确认。

## 7. 文件树服务端分页与资源收尾

- 问答状态收敛到内部 `useRepositoryQa`。关闭面板保留同一项目的完成对话和输入草稿；关闭、切换项目或已知源码版本变化后，取消前端等待，拒绝迟到的成功、错误和 loading 收尾。停止等待不保证模型服务停止计算，绝不自动重试。
- 同步、全量分析或有变化增量分析成功后，新问题不再携带旧版本的上下文。已有回答不因版本变化被自动删除；无变化增量保持原会话上下文。
- 只有当前版本的成功完整问答轮次进入追问历史，引用校验失败的答案及孤立失败问题不进入。前端发送最近最多 5 轮，每条不超过 4,000 字符，符合现有请求契约；模型生成仍遵循后端既有的最近 6 条历史窗口。
- 失败重试原位更新该问题，使用其失败前的成功上下文，不夹带之后的问题或重复追加用户文本；切换模型本身不发请求，重试不清除下一条问题草稿。跨版本重试清空原上下文。同步提交锁防止重复 Enter 事件产生多个请求。
- 后端在检索前记录分析上下文，在检索后和模型生成后重新核验；生成后再次读取实际文件，验证项目归属、路径、索引哈希与证据片段。重分析、同步、文件变化或删除会使旧回答以现有中文错误返回，不标记为已校验。
- 源码查看器校验返回文件 ID 与路径。问答引用还按原行号精确比对公开片段，保持空白及后端前 1,600 个 Unicode 码点的截断规则。文件 ID 被复用、行号移动或证据变更时，不显示或复制错误正文；普通搜索与耦合定位不受问答专用比对影响。
- 同文件但不同路径或证据会重新读取；修改问答草稿不重建已完成 transcript，避免输入时反复滚动到底部。

### 使用边界

1. 会话仍是当前页面内存状态：本次只保证关闭/重开同项目面板保留，不提供跨项目历史管理、刷新恢复或持久化聊天。
2. 前端版本隔离针对本页面已知的成功分析/同步。其他浏览器触发的更新没有持久化版本协议，不能宣称跨客户端完全一致。
3. 后端复用单进程、有容量上限的分析缓存代际，并检查最新数据库标量与引用源码。缓存淘汰时会保守拒绝进行中的回答，不等同于跨进程分布式版本控制。
4. 查看引用时的前端校验只覆盖公开片段，不证明截断后的全部内容或整个文件从未变化；后端的生成后检查才包含当时引用文件的全文哈希。
5. 尚未新增“历史版本”标签或统一停用旧引用入口，该界面方案等待用户确认。原“证据已校验”仅代表回答生成时的核验，不是持续的实时保证。引用可点击，但读取不匹配时会阻止展示。
6. 这些测试验证会话、检索版本和引用路径，不代表生成模型结论在语义上正确；真实回答准确率仍需单独授权后评测。

# DevAtlas 详细使用报告

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 产品名称 | DevAtlas |
| 产品定位 | 本地优先的代码仓库分析与理解平台 |
| 适用版本 | `v0.9.x` 当前开发版本 |
| 文档日期 | 2026-08-27 |
| 默认前端地址 | `http://localhost:5173` |
| 默认后端地址 | `http://localhost:8000` |
| API 文档地址 | `http://localhost:8000/docs` |
| 默认数据目录 | 项目根目录 `data/` |

本报告面向 DevAtlas 的日常使用者、项目演示者和维护者，说明如何启动系统、导入仓库、查看分析结果、生成报告、处理错误以及管理本地数据。

---

## 2. 产品概述

DevAtlas 用于在本地导入和分析代码仓库。系统不会执行被分析项目中的代码，而是通过文件扫描、Tree-sitter 语法解析、BM25 与本地向量检索、确定性质量规则生成以下结果：

- 仓库文件树；
- 函数、方法、类和接口等代码符号；
- 文件之间的导入关系；
- 解析问题；
- BM25 代码搜索结果；
- 完整源码查看与命中关键词高亮；
- 项目内依赖图和循环依赖；
- 质量评分、规则命中项和修改建议；
- 本地规则或可选大模型增强的 Markdown 分析报告；
- 全量分析和增量分析结果。

系统采用 React、TypeScript、FastAPI、SQLite 和 Tree-sitter。默认使用本地规则引擎时，不需要付费模型、不需要 API Key，也不需要将源码发送给外部服务。

## 3. 使用前准备

### 3.1 本地开发环境

建议准备：

- Python 3.11 或更高版本；
- Node.js 20.19+ 或 22.12+；
- npm；
- Windows PowerShell；
- 可选：Docker Desktop；
- 可选：Ollama 本地模型服务。

### 3.2 支持的仓库来源

| 来源 | 适用场景 | 是否需要网络 | 是否复制到 DevAtlas 数据目录 |
|---|---|---:|---:|
| ZIP 压缩包 | 已下载或需要固定版本的仓库 | 否 | 是 |
| 本地文件夹 | 分析电脑上已有项目 | 否 | 是 |
| 公开 GitHub URL | 直接导入公开仓库默认分支 | 是 | 是 |

### 3.3 支持扫描的文件类型

DevAtlas 当前识别以下主要语言扩展名：

```text
C、C++、C#、CSS、Go、HTML、Java、JavaScript、TypeScript、
Kotlin、PHP、Python、Ruby、Rust、SCSS、SQL、Swift、Vue
```

同时扫描 `.json`、`.md`、`.toml`、`.txt`、`.yaml`、`.yml` 和 `.env` 等文本文件。

默认忽略以下常见目录：

```text
.git、.idea、.mypy_cache、.pytest_cache、.venv、.vscode、
__pycache__、build、coverage、dist、node_modules、target、vendor
```

## 4. 启动系统

### 4.1 Windows 本地启动

在第一个 PowerShell 窗口启动后端：

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
python -m uvicorn app.main:app --reload
```

在第二个 PowerShell 窗口启动前端：

```powershell
cd frontend
npm install
npm run dev
```

浏览器打开：

```text
http://localhost:5173
```

启动成功的判断标准：

1. `http://localhost:8000/api/health` 返回健康状态；
2. `http://localhost:5173` 可以显示项目管理页；
3. 左侧状态区域显示本地模式；
4. 点击“导入仓库”能够打开导入窗口。

### 4.2 Docker Compose 启动

在项目根目录执行：

```powershell
docker compose up --build
```

随后访问：

```text
http://localhost:8080
```

Docker 模式仍将数据库、仓库和模型配置持久化在宿主机的 `data/` 目录中。

### 4.3 环境配置

如需修改默认设置，将 `.env.example` 复制为 `.env`：

```powershell
Copy-Item .env.example .env
```

可配置字段：

| 变量 | 默认值 | 用途 |
|---|---|---|
| `DEVATLAS_ENV` | `development` | 运行环境标识 |
| `DEVATLAS_DATABASE_URL` | `sqlite:///./data/devatlas.db` | SQLite 数据库位置 |
| `DEVATLAS_REPOSITORY_ROOT` | `./data/repositories` | 导入仓库保存目录 |
| `DEVATLAS_PROVIDER_CONFIG_PATH` | `./data/report-providers.json` | 模型接口配置文件 |
| `DEVATLAS_TEMPORARY_ROOT` | `./data/tmp` | ZIP 上传和 GitHub 下载临时目录 |
| `DEVATLAS_SEARCH_INDEX_ROOT` | `./data/indexes` | 搜索与智能问答持久化索引目录 |
| `DEVATLAS_SEMANTIC_SEARCH_ENABLED` | `true` | 是否启用本地向量检索与语义重排 |
| `DEVATLAS_MAX_UPLOAD_MB` | `200` | 上传或 GitHub 下载压缩包上限 |
| `DEVATLAS_ALLOWED_ORIGINS` | `http://localhost:5173` | 允许访问后端的前端来源 |

修改配置后需要重启后端。

## 5. 界面使用逻辑

DevAtlas 采用“先选择项目，再选择功能”的工作方式。

左侧区域由两部分组成：

1. 当前项目选择器：用于切换已经导入的项目；
2. 功能菜单：仓库概览、代码搜索、依赖图谱、影响分析、分析快照、质量检测和分析报告。

没有选择项目时，项目相关功能不可用。选择项目后，所有菜单都围绕该项目展示数据。浏览器 URL 会保存当前项目、功能和标签页，刷新页面后可以恢复工作位置。

## 6. 导入仓库

### 6.1 导入 ZIP 压缩包

操作步骤：

1. 点击右上角“导入仓库”；
2. 选择“ZIP 压缩包”；
3. 点击选择文件；
4. 选择一个 `.zip` 文件；
5. 等待后台完成保存、扫描、解析、索引和整理结果；
6. 完成后系统自动进入新项目。

限制与说明：

- 默认 ZIP 上传上限为 200 MB；
- 解压后的总大小不能超过 500 MB；
- 系统会拒绝绝对路径和包含 `..` 的危险路径；
- 空压缩包、损坏压缩包和伪 ZIP 文件会被拒绝；
- 下载或上传阶段的临时 ZIP 最终会自动删除。

### 6.2 导入本地文件夹

操作步骤：

1. 点击“导入仓库”；
2. 选择“本地文件夹”；
3. 从系统文件管理器把项目根目录拖入虚线区域；支持安全目录 API 的外部浏览器也可以点击选择；
4. 浏览器通过拖放惰性遍历或安全目录 API 逐层扫描，在进入目录前自动排除依赖、缓存和构建产物；
5. 检查“原始文件夹 / 自动排除 / 待分析源码”统计；
6. 点击“确认并开始分析”；
7. 等待后台分析完成。

注意：

- DevAtlas 会在 `data/repositories/` 中保存一份受管理副本；
- 默认最多上传 20000 个待分析源码文件、总计 200 MB，单个源码文件不超过 5 MB；
- `.git`、`node_modules`、虚拟环境、缓存、构建目录和二进制资源会在上传前自动排除；
- 扫描过程具有目录深度、扫描条目、源码文件数量和体积熔断，并可随时取消；
- 不支持点击式安全目录 API 的内置浏览器可以使用文件夹拖放入口，系统不会恢复高风险的整目录枚举；
- 后续修改原始文件夹不会自动同步到 DevAtlas 副本；
- 如需分析最新内容，应重新导入，或直接修改 DevAtlas 管理的仓库副本后运行增量分析；
- 浏览器可能在选择大型文件夹时需要较长时间整理文件列表。

### 6.3 导入公开 GitHub 仓库

支持的地址格式：

```text
https://github.com/owner/repository
https://github.com/owner/repository.git
```

操作步骤：

1. 点击“导入仓库”；
2. 选择“GitHub 仓库”；
3. 粘贴仓库根地址；
4. 点击导入；
5. 等待下载和分析完成。

GitHub 导入的实际行为：

- 下载默认分支的 `HEAD.zip` 源码快照；
- 不执行 `git clone`；
- 不包含 `.git` 目录、提交历史、其他分支和标签；
- 只支持公开仓库和 HTTPS 地址；
- 默认下载上限为 200 MB；
- 下载过程只使用项目内的 `data/tmp/` 临时目录，不使用 Windows 默认的 C 盘临时目录，完成后临时 ZIP 会删除；
- 解压后的仓库长期保存在 `data/repositories/`。

如果 GitHub 导入失败，可以根据提示检查：

- 地址是否为仓库根地址；
- 仓库是否公开；
- 后端是否具备外网访问权限；
- 当前网络是否可以访问 GitHub；
- 是否遇到匿名下载限流；
- 仓库压缩包是否超过大小限制。

### 6.4 后台任务阶段

导入时界面会展示以下阶段：

| 阶段 | 含义 |
|---|---|
| 排队 | 任务已经创建，等待开始 |
| 保存 | 保存上传内容或下载 GitHub 快照 |
| 扫描 | 识别文件、语言、行数和哈希 |
| 解析 | 使用 Tree-sitter 提取符号与导入关系 |
| 索引 | 构建 BM25 搜索数据 |
| 整理 | 生成项目汇总信息 |
| 完成 | 项目可以使用 |
| 失败 | 显示原因和处理建议 |

不要在导入进行中关闭后端。前端页面关闭后，已开始的后台任务通常仍会继续，但建议等待界面显示完成。

## 7. 项目选择与管理

### 7.1 选择项目

1. 点击左侧当前项目区域；
2. 在项目列表中选择目标项目；
3. 系统加载项目详情和结构数据；
4. 之后可以在各功能菜单间切换。

切换项目会关闭当前源码查看器，并清空上一个项目的搜索、图谱、质量和报告临时状态，避免混用不同项目的数据。

### 7.2 返回项目管理

在项目选择器中使用返回项目列表的入口，可以查看全部已导入仓库、文件数量、代码行数、主要语言和更新时间。

### 7.3 删除项目

项目列表右侧的删除按钮会：

1. 删除 SQLite 中对应的项目、文件、符号、依赖、问题和搜索索引记录；
2. 删除 `data/repositories/` 中由 DevAtlas 管理的仓库副本；
3. 不会删除最初选择的本地原始文件夹；
4. 不会删除 GitHub 上的在线仓库。

删除是不可恢复操作。需要保留结果时，应先导出分析报告或备份 `data/` 目录。

## 8. 仓库概览

仓库概览用于查看项目基础分析结果，包含“文件、符号、依赖、问题”四个标签。

### 8.1 文件

文件以树形层级展示：

- 目录可以展开和收起；
- 缩进、连接线和目录标识用于区分层级；
- 文件行显示名称、语言、大小或行数等信息；
- 当前版本的文件树主要用于浏览分析范围。

如果某个文件没有出现，常见原因包括：

- 文件扩展名不在扫描范围；
- 文件位于默认忽略目录；
- 文件是符号链接；
- 文件包含二进制内容；
- 文件读取失败。

### 8.2 符号

符号标签展示 Tree-sitter 识别出的：

- 函数；
- 方法；
- 类；
- 接口；
- 符号限定名称；
- 所在文件和起止行号。

符号数量为零时，应先检查项目语言是否已支持、代码是否存在语法错误，以及文件是否超过解析限制。

### 8.3 依赖

依赖标签展示源文件中的导入关系，包括：

- 导入语句所在文件；
- 导入目标文本；
- 所在行号；
- 是否成功解析为项目内部文件。

外部包通常不会解析为项目文件，这是正常现象。项目内相对导入或模块导入解析成功后，会参与依赖图和循环依赖检测。

### 8.4 问题

问题标签主要展示解析阶段发现的问题。界面以英文解析器原始信息为主，并增加一条中文说明，帮助判断影响。

常见情况：

- 语法错误导致部分符号无法提取；
- 文件超过 Tree-sitter 解析上限；
- 文件路径不符合安全范围；
- 某种语法暂未被当前查询规则覆盖。

解析问题不等同于代码一定不能运行，只表示 DevAtlas 可能无法完整理解该文件。

## 9. 全量分析与增量分析

### 9.1 全量分析

点击仓库概览中的“全量”会重新：

- 扫描全部支持文件；
- 计算文件元数据和内容哈希；
- 解析全部符号与导入关系；
- 更新解析问题；
- 重建 BM25 搜索索引。

适合以下情况：

- 首次排查分析结果异常；
- 解析器或分析规则升级；
- 数据库结果与文件内容明显不一致；
- 需要重新建立完整索引。

### 9.2 增量分析

点击“增量分析”时，系统先比较文件大小和纳秒级修改时间；只有元数据变化时才进一步计算 SHA-256，并只重新解析真正变化的文件。

结果会显示：

- 新增文件数；
- 修改文件数；
- 删除文件数；
- 跳过的未变化文件数；
- 实际重新解析文件数；
- 本次耗时。

适合日常修改后快速刷新分析结果。仓库没有变化时，增量分析通常明显快于全量分析。

### 9.3 如何选择

| 情况 | 建议 |
|---|---|
| 只修改了少量文件 | 增量分析 |
| 删除或新增了部分文件 | 增量分析 |
| 升级了解析规则 | 全量分析 |
| 数据显示明显异常 | 先增量，仍异常再全量 |
| 源码查看提示文件已移动或删除 | 增量分析 |

## 10. 代码搜索与源码查看

### 10.1 使用 BM25 搜索

1. 选择一个项目；
2. 点击左侧“代码搜索”；
3. 输入函数名、类名、变量名、模块名或关键词；
4. 点击搜索；
5. 查看结果文件、符号、行号、代码片段和相关性得分。

搜索结果按 BM25 相关性排序。统计区域会区分：

- 总匹配数；
- 当前已经展示的匹配数；
- 已索引代码块数量；
- 查询耗时。

当结果超过单页数量时，点击“加载更多”。加载完成后，显示数量应逐步接近总匹配数。

### 10.2 搜索建议

- 优先搜索具有区分度的函数名或类名；
- 下划线命名和驼峰命名会进行一定程度的拆词；
- 过短或常见词可能产生大量低区分度结果；
- 搜索不到刚修改的内容时，先执行增量分析；
- 搜索只覆盖已扫描和已建立索引的文本源码。

### 10.3 打开完整源码

点击搜索结果右侧“查看代码”后，可以：

- 查看完整文本源码；
- 查看文件路径、语言、总行数和匹配范围；
- 自动滚动到首个匹配区域；
- 高亮搜索关键词；
- 复制文件路径；
- 复制完整源码；
- 按 `Esc` 或关闭按钮退出。

源码查看限制：

- 单个文件不能超过 2 MB；
- 二进制文件不能打开；
- 文件必须属于当前项目；
- 解析后的路径必须位于仓库根目录内；
- 接口只读，不会修改或执行源码。

加载失败时，界面会显示原因、建议和“重新读取”按钮。例如文件在磁盘中已被移动时，会建议执行增量分析刷新索引。

## 11. 依赖图谱

依赖图谱只展示已经解析为项目内部文件的依赖关系。

主要信息包括：

- 节点数量；
- 边数量；
- 项目内依赖数量；
- 循环依赖数量；
- 每个节点的入度和出度；
- 依赖关系所在行号。

常用操作：

- 使用路径关键词筛选节点；
- 放大或缩小图谱；
- 点击节点查看文件路径、入度、出度和相邻节点；
- 查看循环依赖列表；
- 根据高入度、高出度节点识别核心模块或耦合热点。

图谱为空不一定是错误，可能表示：

- 项目只有一个源文件；
- 文件只依赖外部包；
- 当前语言的导入解析尚未覆盖；
- 导入文本无法解析为项目内文件；
- 需要重新运行全量分析。

### 11.1 修改影响分析

1. 点击左侧“影响分析”，输入文件路径、类名或函数名；也可以在仓库文件树或符号列表点击“影响”。
2. 从匹配结果中选择一个具体对象。
3. 查看定义位置、直接调用者、被调用对象与依赖、二级影响模块、相关测试、相关接口、数据库实体和循环依赖。
4. 点击任意结果可打开源码并定位到对应行。

文件级结果来自已经解析的项目内导入关系，可信度较高。函数、方法和类级关系来自符号定义、源码引用和模块依赖的有限范围静态推断，页面会显示置信度；它不会执行项目代码，也不代表完整运行时调用链。

风险分数用于确定回归检查范围，不表示代码本身存在缺陷。直接调用者、二级影响、循环依赖、接口层和数据库层会提高风险；定位到相关测试会降低验证风险。

## 12. 质量检测

质量检测基于确定性静态规则，不需要大模型。

### 12.1 当前规则

| 规则 | 默认阈值 | 含义 |
|---|---:|---|
| 超长函数 | 80 行 | 函数或方法可能承担过多职责 |
| 超大类 | 500 行 | 类或接口维护和测试成本可能较高 |
| 超大文件 | 1,000 行 | 文件可能需要按职责拆分 |
| 导入过多 | 25 条 | 文件耦合度可能过高 |
| 高扇出模块 | 10 个内部目标 | 模块可能成为架构耦合点 |
| 循环依赖 | 出现依赖环 | 初始化和重构风险较高 |

### 12.2 阅读质量报告

质量页面包括：

- 0～100 分质量分；
- A～F 等级；
- 错误、警告和提示数量；
- 每条规则的命中数量；
- 文件路径和起止行号；
- 实际指标与规则阈值；
- 针对该问题的修改建议。

可以按严重级别和检测规则筛选问题。

质量分用于项目内相对比较，不应被视为代码正确性的绝对结论。规则没有命中，也不代表不存在业务错误、安全漏洞或测试不足。

## 13. 分析报告

### 13.1 报告内容

分析报告综合以下本地数据：

- 项目基本规模；
- 主要语言；
- 文件、符号和导入统计；
- 依赖热点和循环依赖；
- 质量评分和主要问题；
- 解析问题；
- 项目风险与建议。

### 13.2 可用分析接口

| 接口 | 默认可用 | 运行位置 | 成本 |
|---|---:|---|---|
| DevAtlas 本地规则引擎 | 是 | DevAtlas 后端 | 免费 |
| Ollama | 配置后 | 本机或局域网模型服务 | 取决于本地硬件 |
| OpenAI Responses API | 配置后 | 在线服务或兼容网关 | 按供应商计费 |

默认建议使用本地规则引擎，可以直接生成报告且不会发送源码到外部模型。

### 13.3 配置 Ollama

Ollama 指本机或局域网部署的模型服务。

操作步骤：

1. 安装并启动 Ollama；
2. 使用 `ollama list` 确认本机已有模型；
3. 在“分析报告”页面点击 Ollama 卡片下方“配置 API”；
4. API 地址填写类似 `http://127.0.0.1:11434`；
5. 模型名称填写 `ollama list` 中的准确名称；
6. 点击“保存配置”；
7. 点击“测试连接”；
8. 连接成功后选择 Ollama 并生成报告。

### 13.4 配置 OpenAI Responses API

操作步骤：

1. 点击在线 Responses API 卡片下方“配置 API”；
2. 服务地址填写 `https://api.openai.com/v1` 或兼容网关地址；
3. 填写账号可用的模型 ID；
4. 填写 API Key；
5. 保存配置；
6. 测试连接；
7. 连接成功后选择该接口生成报告。

注意：

- 当前入口使用 Responses 协议；
- DeepSeek 和 Claude 的原生 API 不一定兼容；
- 如需连接原生 DeepSeek Chat Completions 或 Anthropic Messages，需要增加对应适配器；
- API Key 不会通过查询接口回传给浏览器；
- 修改已有配置时，API Key 留空表示保留原密钥。

### 13.5 接口状态

| 状态 | 含义 |
|---|---|
| `READY` | 本地接口可直接使用 |
| `NEED_CONFIG` | 尚未填写配置，卡片不可选择 |
| `CONFIGURED` | 已保存配置，但尚未确认连接成功 |
| `CONNECTED` | 连接测试成功 |
| `CONNECTION_FAILED` | 地址、模型、密钥或网络存在问题 |

从 Ollama 或在线接口切回本地分析后，API 配置表单会自动关闭。

### 13.6 导出 Markdown

“导出 MD”只在分析报告页面出现。

操作步骤：

1. 选择分析接口；
2. 生成或重新生成报告；
3. 检查页面中的 Markdown 预览；
4. 点击“导出 MD”；
5. 在支持系统保存窗口的浏览器中选择目录和文件名；
6. 如果浏览器不支持路径选择，文件会保存到默认下载目录。

建议导出后使用 VS Code、Typora 或支持 Markdown 的编辑器检查内容。

## 14. 错误提示与处理方法

新版错误提示采用以下结构：

```text
操作失败：明确原因。建议：下一步操作。
```

### 14.1 常见错误处理表

| 提示场景 | 可能原因 | 建议处理 |
|---|---|---|
| 无法连接 DevAtlas 本地后端 | 后端未启动或 8000 端口不可访问 | 启动后端并访问 `/api/health` |
| 项目不存在或已被删除 | URL 保存了旧项目 ID | 刷新项目列表并重新选择 |
| 源文件已删除或移动 | 数据库索引与仓库副本不一致 | 执行增量分析 |
| 文件超过 2 MB | 源码查看器安全限制 | 使用本地编辑器查看或拆分文件 |
| 二进制文件不能显示 | 文件不是文本源码 | 选择文本或源代码文件 |
| GitHub 仓库不存在 | 地址错误、仓库私有或已删除 | 检查 URL 和公开权限 |
| 无法连接 GitHub | 网络、代理或后端外网权限问题 | 检查网络，或改用 ZIP 导入 |
| GitHub 下载超时 | 网络慢或仓库较大 | 重试或本地下载 ZIP 后导入 |
| ZIP 包含危险路径 | 压缩包中存在绝对路径或 `..` | 重新打包仓库 |
| 模型接口未配置 | 地址、模型或密钥未保存 | 点击“配置 API”并测试连接 |
| 模型连接失败 | 地址、模型、密钥、网络或协议不匹配 | 分项检查并使用测试连接 |
| 搜索没有最新代码 | 仓库文件变化后索引未刷新 | 执行增量分析 |
| 依赖图为空 | 只有外部依赖或解析未命中 | 查看依赖标签并尝试全量分析 |

遇到提示后应优先按界面中的“建议”处理。问题持续存在时，再查看后端终端日志和浏览器开发者工具中的网络请求。

## 15. 数据、磁盘空间与备份

### 15.1 默认数据位置

```text
data/
├─ devatlas.db              SQLite 数据库
├─ repositories/            ZIP、本地文件夹和 GitHub 仓库副本
├─ report-providers.json    可选模型接口配置
├─ reports/                 预留的报告数据目录
├─ indexes/                 BM25 与智能问答向量索引
└─ models/                  本地语义嵌入模型缓存
```

如果项目根目录位于 D 盘，以上持久化数据也位于 D 盘。

GitHub 或 ZIP 导入时，临时压缩包位于 `DEVATLAS_TEMPORARY_ROOT` 指定的目录，默认是项目内的 `data/tmp/`；不会占用 Windows 默认的 C 盘临时目录，处理结束后会自动删除。解压后的长期数据保存在 `DEVATLAS_REPOSITORY_ROOT` 指定的位置。

### 15.2 备份

关闭后端后，备份整个 `data/` 目录即可保留：

- 项目记录；
- 仓库副本；
- 分析结果；
- 搜索索引数据；
- 本地语义嵌入模型缓存；
- 模型接口配置。

示例：

```powershell
Copy-Item -Recurse data "D:\backup\devatlas-data"
```

模型配置可能包含 API Key，备份目录应妥善保护，不要提交到 GitHub。

### 15.3 清理空间

优先通过 DevAtlas 项目列表删除不需要的项目，使数据库记录和仓库副本同步清理。

不要在后端运行期间手动删除 `devatlas.db`。如果直接删除 `data/repositories/` 中的目录，数据库仍会保留旧记录，随后源码查看和重新分析可能提示文件不存在。

## 16. 隐私与安全边界

DevAtlas 当前的主要安全措施：

- 不执行被分析仓库中的代码；
- ZIP 解压检查绝对路径和 `..` 路径穿越；
- GitHub 导入限制为公开仓库根地址和允许的 GitHub 下载域名；
- 下载具有连接、读取和总大小限制；
- 文件扫描跳过符号链接和二进制文件；
- 源码查看接口校验项目与文件归属；
- 源码路径必须位于项目仓库根目录内；
- API Key 不写入前端代码、不通过查询接口回传；
- `data/` 目录默认被 Git 忽略；
- 默认本地报告不会调用任何外部模型。

需要注意：

- 主动选择在线模型生成报告时，报告上下文会发送给配置的服务；
- 不应在公开部署的 DevAtlas 实例中分析未经审查的敏感仓库；
- `data/report-providers.json` 可能包含认证信息，应限制文件访问权限；
- DevAtlas 不是恶意代码沙箱，也不是完整的安全审计工具。

## 19. 常见问题

### 19.1 是否必须使用数据库？

需要。SQLite 用于持久化项目、文件元数据、哈希、符号、导入关系、解析问题、搜索片段和后台任务。原始仓库文件仍保存在本地文件系统中。

### 19.2 是否必须配置大模型？

不需要。本地规则引擎可以直接生成分析报告。

### 19.3 Ollama 是否属于本地模型？

是。Ollama 通常运行在本机，也可以配置为局域网中的 Ollama 服务。

### 19.4 在线 Responses API 是否等于所有在线模型 API？

不是。当前入口面向 OpenAI Responses 协议。其他供应商只有在提供兼容网关时才能直接使用，原生 DeepSeek 或 Claude 协议需要额外适配。

### 19.5 GitHub 导入是否会下载全部提交历史？

不会。只下载默认分支当前 `HEAD` 的 ZIP 快照。

### 19.6 导入仓库是否占用本地空间？

会。解压后的仓库副本长期保存在 `data/repositories/`，数据库保存在 `data/devatlas.db`。

### 19.7 为什么文件数量少于仓库实际文件数量？

DevAtlas 只统计支持的文本和源代码扩展名，并忽略构建目录、依赖目录、二进制文件和符号链接。

### 19.8 为什么符号或导入数量为零？

可能是语言解析尚未支持、代码存在语法错误、文件超过限制、仓库只有配置文件，或需要重新进行全量分析。

### 19.9 为什么搜索总匹配数与当前结果数不同？

搜索采用分页加载。总匹配数表示全部结果，当前显示数表示已经加载到页面中的结果。点击“加载更多”可以继续获取。

### 19.10 为什么导出没有让我选择路径？

部分浏览器不支持系统文件保存选择器，会退化为保存到浏览器默认下载目录。

## 20. 当前限制与后续建议

当前主要限制：

- 文件树尚未直接连接源码查看器；
- 符号和导入关系尚未支持一键跳转源码；
- 源码查看器暂不提供文件内搜索和上下一个匹配；
- 只对部分语言提供 Tree-sitter 结构查询；
- 向量语义检索目前只服务于智能问答，代码搜索页面仍以可解释的 BM25 结果为主；
- 在线模型入口主要支持 Responses 协议；
- 后台任务暂不支持用户主动取消；
- SQLite 更适合单机和个人演示，不适合作为高并发多人服务数据库。

推荐下一阶段优先实现：

1. 文件树点击打开源码；
2. 符号跳转到定义行；
3. 导入关系跳转目标文件；
4. 源码文件内搜索和上一个/下一个匹配；
5. 报告问题点击跳转源码证据；
6. 仓库健康检查与缺失文件修复入口。

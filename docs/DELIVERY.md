# DevAtlas 发布与简历交付清单

本文区分“仓库已有的工程能力”和“每次推送仍须重新完成的验收”。最近一次测试数量及覆盖率见 [根 README 的可量化结果](../README.md#可量化结果)；[文档导航](./README.md) 按正确性、性能和历史记录分组。本清单不代表打开文件时已经完成一次新的发布检查。

## 1. 已有交付基础

- [x] 根目录 README 包含定位、技术栈、启动、测试和API入口。
- [x] `docs/` 集中保存架构、计划、性能、演示和截图。
- [x] 本地开发与 Docker 挂载默认使用根目录 `data/`，可按环境配置位置。
- [x] `.env.example` 提供无敏感信息的配置模板。
- [x] 数据库、导入仓库、API Key、依赖和构建产物已加入 `.gitignore`。
- [ ] 由项目所有者选择开源许可证，并检查第三方依赖许可证；不能以公开仓库替代许可证，也不在整理时自动替用户选择。

已有 Ruff、Pytest 覆盖率门禁、Vitest、生产构建及 Playwright；配置见 [CI](../.github/workflows/ci.yml)，不是只看徽章就认定本地未提交内容已验证。

## 2. 每次提交前：确定内容与隐私边界

- [ ] 使用 `git status --short`、`git diff --stat` 与 `git diff --check` 确认改动范围；不删除或覆盖不属于本次任务的改动。
- [ ] 检查待暂存和已暂存文件，排除 `.env`、密钥配置、数据库、导入源码、模型缓存、索引和完整 `data/tmp/` 运行目录；`.gitignore` 不会自动排除已经跟踪的敏感文件。
- [ ] 保留有意纳入版本控制且已审查的 `benchmarks/` 标注、评测摘要和 `docs/performance/` 证据；不删除难例、重写历史结果或更改源码锁来制造全绿。
- [ ] 检查截图与示例中没有 API Key、私人仓库内容、敏感路径或通知信息。
- [ ] 确认运行数据在选定的非系统盘目录。本机项目位于 D 盘；换机器时按 README 和环境配置检查，不把示例路径当成自动迁移结果。

## 3. 每次提交前：执行适当验证

在已有依赖的项目根目录执行常规验证：

```powershell
.\scripts\verify_project.ps1
```

[脚本](../scripts/verify_project.ps1) 检查本地 Markdown 链接、Ruff、后端测试与 85% 覆盖率门禁、36 道合成证据回归、前端单测、生产构建及 Playwright。每次在项目的 `data/tmp/verification/run-*` 下隔离数据库、仓库、索引、空模型配置和临时目录，关闭语义模型联网，退出时恢复原环境。`-SkipE2E` 只适用于明确记录未执行浏览器验收的场合，不能称为完整验证。

也可单独执行与 CI 对齐的合成证据评测命令（完整脚本已包含此项）：

```powershell
cd backend
.\.venv\Scripts\python.exe -m evaluations.repository_qa
```

- [ ] 记录每项命令、通过/失败、运行范围和是否实际重跑；不得把上一轮的测试数量标成这次重新测得。
- [ ] 确认 Playwright 使用隔离的 `8011/5175` 服务和 `data/tmp/e2e/run-*`（完整脚本使用本次验证目录的 `e2e/`），不复用日常服务、项目或模型配置。
- [ ] 在全新目录按 README 做冷启动与关键流程检查；未执行时保持待办，不用旧开发环境代替。
- [ ] 用模拟请求回归模型认证失败、超时与密钥脱敏；真实模型调用须另行确认，不是常规检查的默认步骤。

常规 CI 的单测/证据回归不自动下载真实仓库或模型，也不调用真实生成模型。CI 安装 Python/npm 依赖及 Chromium 仍访问网络，“证据评测离线”不等于整条 CI 禁网。微基准耗时、真实语料和真实回答评测不自动成为每次提交的 CI 门禁。

### 额外评测：先准备，再显式运行

| 验证目标 | 前置条件与入口 |
|---|---|
| 合成检索/引用回归 | 仓库已附合成样例；按 [QA_EVALUATION.md](./QA_EVALUATION.md) 离线运行，不调用生成模型 |
| 真实仓库检索对照 | 用户显式准备固定本地 corpus 后，按 [QA_REAL_EVALUATION.md](./QA_REAL_EVALUATION.md) 与 [QA_RECHECK.md](./QA_RECHECK.md) 运行；语义组还需已有本地嵌入模型，缺失时不能静默降级 |
| 真实耦合探针 | 同样先准备固定本地 corpus；按 [COUPLING_REAL_EVALUATION.md](./COUPLING_REAL_EVALUATION.md) 校验并运行，工具本身不自动下载语料或调用模型 |
| 真实生成回答 | 先由用户选择并配置 Ollama 或在线生成模型、确认调用范围；不能把本地嵌入模型或本地报告规则当作免费默认问答模型 |
| 性能复测 | 按 [文档导航的性能记录](./README.md#性能记录) 选择既有脚本，保持环境、样本与统计口径可比，保留退步及失败记录 |

真实源码不会随普通克隆自动获得。若尚未准备，先确认下载/本地语料路径再使用文档中的显式准备命令。输入漂移、目标歧义、失败题或模型未就绪都应如实报告，不通过放宽标准、改标注或忽略退出码消除失败。

## 4. 核验后推送，与 Release 分开

1. 检查 `git remote -v` 和当前分支，确认目标确为用户授权的仓库；不要隐式变更可见性。
2. 只暂存已审查的文件，再用 `git diff --cached --stat` 和 `git diff --cached --check` 复核后提交；不使用强制推送覆盖远端历史。
3. 推送用户授权的分支，保存提交号并查看该提交的 CI 结果。推送成功与 CI 通过是两件事，仍在运行或失败须分别说明。
4. 用户需要新版本发布时，再准备对应版本说明和标签。普通代码推送不应顺带推送全部标签。

[Release 工作流](../.github/workflows/release.yml) 在推送 `v*` 标签时创建 GitHub Release，优先使用 `docs/releases/<标签>.md`；`v0.*` 标为预发布。它不等待 CI 自动验证该标签，因此创建新标签前应确认目标提交已经验收，并获得发布范围确认。

- 全量重新分析中位数：167.97ms。

- 同口径最高加速比：15.41×。
- 大型项目：929个文件、40,515行代码；无变化增量分析中位数287.54ms。

性能数字的适用边界和原始样本参见 [PERFORMANCE.md](./PERFORMANCE.md)。

检索命中率不是生成回答准确率；固定耦合探针通过不等于完整调用图准确率；静态相关测试不等于测试通过或执行覆盖率。报告规则可以免模型运行，但智能问答须配置生成模型，在线服务可能产生费用，本地服务需要用户自行准备模型和运行资源。

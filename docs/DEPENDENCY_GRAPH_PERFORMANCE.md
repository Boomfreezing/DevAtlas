# 依赖图谱：交互性能与请求一致性

后续阶段已完成[生产构建与文本节点优化验收](./DEPENDENCY_GRAPH_PRODUCTION.md)。本文保留上一轮开发构建数据及回退记录，不与生产结果混算。

更新日期：2026-09-12。继[多目录文件树阶段](./FILE_TREE_DENSE_PERFORMANCE.md)之后，本轮仅完善既有依赖图谱，不新增菜单、后端接口、库或数据表，不恢复全量函数调用图；没有真实模型调用、仓库同步或 GitHub 推送。

## 本轮修改

### 读取与状态

- 首次图谱读取统一由页面生命周期管理，离页、切换项目和索引更新取消过期 GET；取消后晚到的成功、失败与 loading 收尾均不得回填。已完成的同项目图谱仍在菜单往返时复用。
- 循环聚焦使用独立读取作用域，改选、退出、卸载及项目/图谱替换会取消旧请求。失败可重试原循环，不把取消当作网络故障。
- 循环加载或失败时，画布与详情不再沿用全局图，分别显示加载、失败提示；真正无匹配时才显示无匹配模块。待加载时暂停筛选和缩放。
- 更新项目或分析数据后，选中对象、循环聚焦、筛选与缩放重置；筛选隐藏当前节点后不会在清空关键词时突然跳回该旧节点，边详情也随筛选清理。
- 加载中重复点击当前图谱菜单不重发；提交中的全量/增量分析不会被导航取消，读图等待分析流程完成。图谱刷新不会清掉分析失败通知。
- 截断图明确说明路径筛选只作用于已加载模块，不将未加载的文件误称为不存在。空图文案也不再断言仓库一定只有外部依赖。

### 绘制与维护性

- 将图谱视图从 `App.tsx` 提取为现有工作区内部组件，纯计算放在 `dependencyGraphModel.ts`；菜单、页面入口与分析数据不变。
- 按图数据和路径筛选准备节点、边、邻接索引、布局与连线几何。缩放只改变视口，选中只更新相关样式和详情，不再重复生成每条曲线路径。
- 循环成员索引保留分组语义：一条边的两个端点属于同一强连通分量才标为循环边；不同分组间的桥边不会因“两端都是循环节点”被误标。后端提供的是强连通分量，不是枚举出的全部简单环路。
- 绘图层、循环列表与详情按稳定参数复用；每 128 条边、64 个节点组成一个绘制批次，只更新含当前或先前选中对象的批次。批次内直接生成 SVG 元素，避免每条边都额外挂载一个 memo 组件；批次不是分页，不减少显示数量。原环形布局、节点数量、边数量和标签策略保持不变。
- 修复互逆边两次反转导致曲线重叠的问题，两个方向现在线段两侧绘制；自依赖使用非退化闭合曲线与箭头，外围节点的自环朝画布中心伸展。
- 节点支持 Tab 聚焦、Enter/空格选择，并沿用绿色 Terminal 焦点样式；边原有键盘操作继续有效。

## 性能测量口径

脚本：[dependency-graph.spec.ts](../frontend/perf/dependency-graph.spec.ts)。原始结果：[修改前](./performance/dependency-graph-baseline.json)、[修改后](./performance/dependency-graph-after.json)。

首轮按每条边/节点单独 memo 的[中间测量](./performance/dependency-graph-after-initial.json)也保留：选中与缩放脚本开销下降，但首次聚焦和部分清空筛选动作变慢。因此最终版改为分组复用，再用相同夹具重测；不删除回退记录，也不把中间最优值拼接成最终成绩。

- 两组夹具各 3 个独立浏览器页面样本，共 6 个样本/版本。默认均显示 40 节点、175 边；聚焦后分别显示 240 节点/1,200 边和 400 节点/2,000 边，保留全部 20 条循环分组。
- 默认界面仍请求 `limit=40`。既有循环聚焦接口按强连通分量返回完整成员，不受默认图的 limit 截断；测量没有通过少显示节点、裁剪边或自动折叠来降低开销。
- 每样本验证 19 个动作阶段，包括进入图谱、选中节点/边、缩放、命中/无命中/清空筛选、循环聚焦与退出。两版使用相同夹具及 SHA-256。
- 语义修复使聚焦时不再显示全局截断提示（少 1 个 DOM 元素）；清空筛选后回到首个可见节点，部分步骤的节点标签由 17 变为 16，邻居详情也随选中对象变化。这不影响节点/边/循环分组的完整数量，但不能说每个 DOM 元素在每一步都完全相同。
- Chrome 152.0.7977.83、Node 24.18.0、Windows，1440×1000 视口，Vite 开发模式。业务 GET 由合成响应提供，非 GET 直接失败；不测远程网络、真实模型或实际仓库解析。
- 交互计时包含 Playwright 通信、动作、断言和两帧等待。密集图选节点用 DOM click，选边用 Enter，其余为正常 click/fill；不是鼠标逐个寻找重叠节点的用户耗时。
- 同时记录 CDP `ScriptDuration` / `TaskDuration` 的区间增量，仍包含自动化在浏览器侧执行的工作，不等于隔离出的 React CPU 时间。没有使用耗时断言作为 CI 门槛。
- JS heap 通过 CDP 强制 GC 后读取；不是 RSS、自然 GC 或进程内存峰值。前后分开采样、每组 3 次，不作统计显著性、P95 或任意设备固定提速承诺。
- 保留采样时源码哈希；基线之后仅修正脚本的 TypeScript 字面量类型断言、扩展实现哈希列表，夹具与计时/交互逻辑未改。修改后的代码不能通过换一个 label 重新生成历史基线。

## 最终实测结果

以下只使用最终分组版本数据，不选取首轮方案中更好的数值。交互列均为 3 次样本中位数，单位 ms，包含自动化、断言与两帧等待。

| 加载规模 / 动作 | 修改前 | 最终版 |
|---|---:|---:|
| 240 节点 / 1,200 边：选中节点 | 253.69 | 97.03 |
| 240：放大 | 113.77 | 90.87 |
| 240：缩小 | 96.01 | 61.88 |
| 240：首次聚焦 | 189.03 | 171.92 |
| 240：清空路径筛选 | 154.08 | 180.71 |
| 400 节点 / 2,000 边：选中节点 | 266.30 | 68.42 |
| 400：放大 | 188.36 | 169.09 |
| 400：缩小 | 132.39 | 69.37 |
| 400：首次聚焦 | 256.81 | 387.64 |
| 400：清空路径筛选 | 397.64 | 420.11 |

400 节点选中的 CDP script 区间中位数为 229.78 → 16.80 ms，放大为 60.22 → 4.15 ms、缩小为 56.00 → 3.49 ms，支持减少重复脚本计算的收益；SVG 绘制、自动化等待等仍占用时间，不能将 script 降幅等同于整个交互提速。

回退必须保留：400 节点首次聚焦仍增加约 130.83 ms（50.94%），清空筛选增加约 22.47 ms。默认 40 节点两组夹具中，选中约 63 → 72–76 ms，首次打开约 136 → 157–163 ms；默认图并未全面加速。分组版本降低了首轮方案的首次聚焦开销，但不能称作已消除大循环重建瓶颈。

强制 GC 后 JS 堆：240 节点聚焦后 14.48 → 13.57 MiB，退出后 11.65 → 9.42 MiB；400 节点聚焦后 **19.25 → 21.20 MiB**，退出后 12.62 → 10.22 MiB。索引和组件复用并非全场景节省内存，不能以退出后的较小值代替峰值或聚焦态数据。

这些是开发构建、固定本机合成场景的小样本诊断，没有统计显著性结论。中间方案与最终方案的实测差异可辅助后续定位，但尚未通过调用栈 profile 精确归因全部首次挂载成本。基准脚本已实际运行通过；独立 perf TypeScript 检查受环境缺少 `@types/node` 限制，本轮未为此新增依赖，不能将生产构建通过解释为 perf 文件也完成了独立类型验收。

## 手动验收

1. 打开依赖图谱，选择一条循环；加载时不应看到无关全局节点，成功后只显示该循环。再次点击或退出聚焦返回全局图。
2. 在请求尚未完成时改选、切换菜单或项目，旧内容与错误不应覆盖当前页面；失败后重试应继续读取原循环。
3. 输入命中路径、完全无匹配路径，再清空；检查节点/边计数、右侧详情同步变化，没有残留的边详情。
4. 用 Tab、Enter/空格选择节点和边，检查源文件与导入行号；放大、缩小后仍可查看详情。
5. 对互相导入的两个文件，两个方向的曲线应分居两侧；对自身导入，应看到自环而不是零长度点。

## 边界与下一步

仍使用 SVG 与原环形布局，数百节点可能拥挤，成千上万条边仍有真实绘制开销；本轮不是 Canvas/WebGL 改造，没有宣布任意规模下不卡顿。数据索引和几何缓存也会增加常驻堆占用，必须与交互收益一并衡量。

路径筛选只搜索当前加载图，不提供全仓库图检索；聚焦完整大分量也没有新增规模上限。取消 GET 不代表后端已启动计算必然立即终止。窗口回退、低性能移动硬件、所有浏览器与完整屏幕阅读器流程尚未覆盖。

下一步优先用**生产构建与浏览器 profile**复查大循环的首次聚焦、筛选重建开销，区分开发模式额外成本与实际 SVG 瓶颈，再局部优化；之后推进既有质量检测的筛选、分页与大列表性能。若需要新绘图库、额外图谱裁剪/分页能力或新入口，先说明影响并征求用户确认。

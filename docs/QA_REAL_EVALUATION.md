# 第一阶段续：真实仓库证据验收与检索对照

## 状态与边界

本轮没有增加菜单、页面或产品功能，没有推送 GitHub，没有使用日常数据库或读取默认模型密钥。只改进既有问答检索，并增加开发者评测工具。

已建立 3 个固定版本真实公开仓库、60 道源码题，以及词法、结构、语义组合的对照入口。真实生成回答的正确性、独立人工复核和真实多轮生成验收仍未完成，不能将本阶段写成“智能问答已全面验收”。

原有 [36 道合成题](./QA_EVALUATION.md) 保留为快速回归门禁，不与真实题库混算。

后续维护说明（2026-09-12）：[文件树与搜索打磨](./STATE_CONSISTENCY.md) 已修正 BM25 零命中片段参与排序的问题，并补齐现有路由单复数词召回；后续证据窗口整理与固定 60 题复测单独记录于[离线检索复测](./QA_RECHECK.md)。下文保留原始历史结果，不与后续实现混算，也不作为当前版本的准确率承诺。

| --- | --- | --- | --- |

固定版本用于可复现源码研究，不是建议用户部署这些历史版本。

- [repositories.json](../benchmarks/repository_qa_real/repositories.json)：公开仓库、标签、完整提交号、ZIP SHA-256 和划分。
- [cases.json](../benchmarks/repository_qa_real/cases.json)：维护者依据源码编写的问题、证据锚点、预期事实与追问关系。锚点在固定源码中解析成路径和行号，不由检索结果反推；歧义、越界或缺少原文会中止评测。
- 51 道源码证据题、6 道明确不存在的标识符题、3 道项目记录题；包含 3 道追问与 3 道话题切换。
- 问题以中文为主，覆盖 Python 和 JavaScript；不代表 TypeScript、大型业务仓库、全部自然语言拒答或复杂多轮场景。
- Flask 部分题目来自真实仓库自带教程，不是另建的合成教程。三者仍主要是库或框架，不能代替实际业务项目验收。
- 标注尚未经独立人工复核。留出仅指未参与调参，标注作者看过源码；公开题库也不保证模型训练时没见过这些开源代码。

首次读取三个公开发布 ZIP 约 5 MB。下载仅允许固定 GitHub codeload 主机、不携带认证、不跟随跳转，验证压缩包哈希和内部提交号后，复用产品现有的路径、大小、文件数量和符号链接安全检查。不会执行、安装或启动被分析仓库。

实际导入的是产品支持的源码/文本文件，不包含被过滤的二进制、依赖目录和不支持的文件类型。运行结果记录导入文件哈希和索引分块数量；因此这是**产品导入视角下的真实仓库证据评测**，不是完整 Git 历史或全格式代码理解基准。

## 本轮检索修正

1. 长函数头部窗口从最多 19 行调整为最多 24 行；对匹配符号增加一段有界的函数体窗口，优先覆盖问题中的状态码、异常或数据库语句。总引用上限仍为 8 条，每条最多 1,600 字符。
2. 定义定位问题优先保留定义头，避免函数体重排后丢失定义行；不通过单纯扩大模型上下文解决问题。
3. 追问的硬性目标来自用户问题，而不是上一条模型回答中的猜测路径；模型给出的路径仍可作为检索提示。用户明确指定的不存在目标仍会被拦截。
4. 用户明确输入的名称优先于“测试”等扩展别名，减少无关 test/user 符号占据前排。
5. 识别 README 中带 `$ ` 提示符的启动命令以及 Flask CLI；真正的启动命令优先于宽泛的 Getting started 描述。

这些是通用检索规则修正，不包含题号、仓库名称分支或固定问题答案映射。它们依据开发集失败题调整，因此开发集收益不是泛化收益。

## 实验组与统计口径

| 模式 | 词法候选 | 本地向量召回 | 结构候选与额外重排 |
| --- | --- | --- | --- |
| `bm25` | 有 | 无 | 无 |
| `structured` | 有 | 无 | 有 |
| `hybrid` | 有 | 有 | 无；词法与语义结果按 RRF 融合 |
| `hybrid-rerank` | 有 | 有 | 有；现有结构扩充、稠密相似度与规则重排 |

所有组沿用产品已有分块、意图路由、查询扩展、目标守卫、引用去重和源码校验。`bm25` 不是未经任何处理的原始 BM25：搜索服务本身已有元数据增强和排序。`hybrid-rerank` 是组合消融，不能将全部变化归因为某一个重排算法。

- Recall@5：每题前 5 条引用覆盖的必要证据比例，再对 51 道源码题平均。要求路径正确、行号完整覆盖锚点、摘录包含关键原文；元数据题与无答案题不进入分母。
- 检索通过：路由正确、全部必要证据在前 5 位、所有引用合法；实现定位题还要求首条不是测试或生成代码。
- MRR：首条必要证据排名的倒数，不代表所有证据齐全。
- 每条引用合法只说明路径、行号、原文有效，不说明模型的全部结论有依据。
- 六道无答案题均为明确不存在的代码标识符，不等于一般性幻觉率或拒答准确率。
- 耗时不含导入、模型加载、向量索引构建；是单次顺序实验，并非稳定性能基准。部分阶段与自动化测试并行，不据此宣传速度提升。
- 模型参数、源码、问题、检索实现和嵌入文件均记录哈希。运行中代码变化会标记 `implementation_unchanged_during_run=false`，该次结果不可作为一致版本的对照。
- 本地向量测试使用已有 BGE 模型文件，`specific_model_path` 和 `local_files_only` 禁止自动下载；模型或索引不可用时失败，不允许悄悄降级后仍标记为 hybrid。

## 本轮实测结果（2026-09-12）

Windows / Python 3.13.5，已有 `BAAI/bge-small-zh-v1.5` 本地模型。三个导入视角下的源码集合分别有 145 / 64 / 194 个文件；索引分块为 Flask 1,690、Requests 831、Express 577。语义组覆盖了这三者的全部已索引分块，没有触及 5,000 分块上限，但不代表原始仓库每个文件都被索引。

| 实验组 | 开发集通过 | 验证集通过 | 留出集通过 | 总通过 | 必要证据 Recall@5 | MRR |
| --- | --- | --- | --- | --- | --- | --- |
| 词法 `bm25` | 11/20 | 9/20 | 10/20 | 30/60 | 45.75% | 0.3734 |
| 结构 `structured` | 17/20 | 11/20 | 11/20 | 39/60 | 63.07% | 0.5193 |
| 词法+语义 `hybrid` | 7/20 | 9/20 | 8/20 | 24/60 | 33.33% | 0.2621 |
| 结构+语义+重排 `hybrid-rerank` | 17/20 | 11/20 | 12/20 | 40/60 | 66.01% | 0.5203 |

四组对六道明确不存在标识符的题目均完成拦截；各组非法引用分别为 0/265、0/325、0/275、0/352。不能将该结果推广成一般幻觉率为零。

结果与实现、模型文件指纹已保存至 [baseline-2026-09-12.json](../benchmarks/repository_qa_real/baseline-2026-09-12.json)，包含逐题是否通过及召回数据。完整原始引用和上下文位于本次本地运行目录 `data/tmp/qa-real-runs/run-44uocf1a/`，未提交到 Git。

### 如何解读

- 结构信息确有帮助，但真实集仍未全部通过。当前完整组合还有 **20 道失败题**，已保留在结果中，没有放宽标准或删除难题。
- 仅合并语义召回反而变差，不能宣传“接入向量检索必然提升准确率”。这也不证明所有语义模型都无效，只说明当前模型、候选融合和题库下的这一组合较弱。
- 完整组合比非语义结构组多通过 1 题，Recall@5 提升 2.94 个百分点；留出集 MRR 却由 0.3374 降到 0.3304。不同指标并非全面上升，不能宣称无条件优于非语义策略。
- 词法、结构、混合、完整重排组的单次题目 P50 分别约 15 / 41 / 58 / 1,435 ms；后者 P95 约 1,835 ms。完整重排有明显耗时成本，本轮不自动切换产品默认策略，也不声称提速。未来应在开发集单独研究重排候选预算和质量/延迟取舍，再换新的留出版本复核。
- 开发阶段非语义结构组从 10/20 改善到最终 17/20；开发集参与了修正，该提升不是独立测试收益。
- 已在开发集确认的剩余问题包括：蓝图前缀与路由定义分散、应用工厂深层注册关系、同一文件多段必要证据与去重预算冲突。后续不能通过一味增加引用数掩盖证据组织问题。

自动化验证：后端 **203 项通过，覆盖率 85.74%**；原有 36 道合成题全部通过；前端 **48 项通过**、生产构建通过；Ruff 与文档链接检查通过。本轮未更改界面，也没有重新运行浏览器 E2E。既有 SQLite 连接释放和第三方 TestClient 弃用警告仍存在，未屏蔽。

以上均不是生成回答准确率。没有调用生成模型，`answer_quality` 保持 `not_measured`；没有进行独立人工复核。

## 复现方式

从项目根目录进入后端，先显式准备固定源码：

```powershell
cd backend
.\.venv\Scripts\python.exe -m evaluations.real_corpus --download
```

仅下载上述三个公开仓库，位置为项目目录下 `data/tmp/qa-real-corpus/`。后续运行只校验本地缓存，不访问 GitHub。当前项目在 D 盘，运行数据不会放入 C 盘临时目录；源码、索引和原始结果均属于已忽略数据，不提交第三方仓库源码。

先运行开发集的无模型对照：

```powershell
.\.venv\Scripts\python.exe -m evaluations.real_repository_qa --split development
```

开发集完成后固定实现，再运行全部划分；也可用 `--split validation` 或 `--split holdout` 分别运行。真实集不会为了全绿而删除难题或自动改写标注。

本机已有嵌入缓存时，可以执行四组对照。下面模型目录为本次已经存在的缓存，其他机器应显式提供自己的完整本地模型目录，工具不会自动下载：

```powershell
.\.venv\Scripts\python.exe -m evaluations.real_repository_qa --split all --modes bm25 structured hybrid hybrid-rerank --embedding-model-dir ../data/models/fastembed/models--Qdrant--bge-small-zh-v1.5/snapshots/46fbe35fd4374a00fee7de77dfddaeb6dd6a2c59
```

每次运行使用内存 SQLite、独立源码副本和索引，保存至 `data/tmp/qa-real-runs/run-*/`。每完成一个实验组，写入该组 `result.json` 和公共 `comparison.md`，中断不会覆盖先前已完成的组。

有未通过题、模型错误或引用失败时退出码为 1，这是实际失败记录，不应改成无条件成功。命令或环境错误为非零退出码；网络/模型不满足时不会宣称完成相应实验。常规 CI 继续离线执行合成回归和评测工具单测，不自动下载仓库或模型、调用收费 API。

## 真实生成回答与人工复核：待确认模型

没有默认读取实际 API 配置，也没有调用生成模型。要测生成回答，需要用户先确认模型通道、配置文件与调用范围。在线模型会收到这些公开仓库的问题、证据片段与有限历史，可能产生费用；不会发送日常导入的私人仓库。

例如选择已经配置好的 Ollama，先运行单题：

```powershell
.\.venv\Scripts\python.exe -m evaluations.real_repository_qa --split development --modes structured --provider ollama --provider-config ../data/report-providers.json --allow-model-calls --case flask-03
```

需要真实连续追问时加 `--generated-history`，并包含对应前置题，例如 `--case flask-09 --case flask-16`。该模式使用实际上一轮生成的回答，不将标注答案偷偷塞入历史。缺少前置题或前置模型调用失败时中止，不能把固定答案模式冒充真实多轮测试。

模型调用阶段沿用同一配置、相同证据上限；报告记录模型名称、实际使用历史和证据字符数。当前适配器不返回可统一计算的 token/费用明细，因此本轮不报告臆测的 token 或金额；费用复核应结合供应商账单。

`manual_review` 按预期事实提供 `supported`、引用编号和备注，并单独记录额外无依据结论。需要维护者逐条核查：

1. 回答是否真正覆盖预期要点，是否将推测写成事实。
2. 指定引用是否支持该事实，不能仅因为出现 `[1]` 就判正确。
3. 是否编造运行时调用、数据库表或测试执行结果。
4. 对缺失实现、外部依赖或截断上下文是否恰当说明边界。
5. 追问能否沿用正确目标，换话题时是否清除错误继承。

只有完成真实生成与人工复核后，才能填写回答正确性。离线报告的 `answer_quality=not_measured` 应保持原样。

# DevAtlas 2～3 分钟演示脚本

## 演示前准备

- 启动后端和前端，打开 `http://localhost:5173/`。
- 准备一个 20～100 个文件、包含 Python 或 TypeScript 的公开示例仓库。
- 提前完成一次导入，避免录屏时受网络下载速度影响。
- 浏览器缩放保持 100%，关闭包含个人信息的窗口和通知。

## 时间轴与讲稿

### 0:00～0:20　项目定位

画面：项目概览页。

讲稿：

> DevAtlas 是我实现的本地优先代码仓库分析平台。它支持 ZIP、本地文件夹和公开 GitHub 仓库，不执行仓库代码，也不依赖付费模型 API。主要技术栈是 React、FastAPI、SQLite 和 Tree-sitter。

### 0:20～0:50　仓库导入与后台任务

画面：打开“导入仓库”，展示三种来源；选择已经准备好的项目。

讲稿：

> 导入过程采用持久化后台任务，页面会展示保存、扫描、解析和索引阶段。ZIP 会进行路径穿越防护，GitHub 下载也有限制域名、重定向、超时和文件大小。

### 0:50～1:20　结构分析

画面：选择项目，切换文件、符号和依赖标签。

讲稿：

> Tree-sitter 会提取 Python、TypeScript 和 JavaScript 的类、函数、方法、行号及导入关系。结果保存到 SQLite，所以刷新或重启服务后不需要重新分析。

### 1:20～1:45　搜索与依赖图

画面：搜索一个函数名，再打开依赖图谱。

讲稿：

> 代码会按函数、类和模块切片，并建立 BM25 索引。依赖图支持路径筛选、缩放、入度和出度查看，并使用强连通分量算法检测循环依赖。

### 1:45～2:10　质量检测

画面：打开质量报告，展示评分和规则筛选。

讲稿：

> 质量模块包含超长函数、超大类、超大文件、导入过多、高扇出和循环依赖六条规则。每个问题都有文件定位、指标、阈值和修复建议。

### 2:10～2:35　增量分析与性能

画面：点击“增量分析”，展示跳过文件数量和耗时。

讲稿：

> 增量分析先走文件大小和修改时间快路径，必要时再计算 SHA-256，并且只重解析变化文件。在 9,553 行测试项目上，无变化增量分析的端到端中位数是 10.9 毫秒，相比全量重新分析加速 15.4 倍。

### 2:35～2:55　工程化收尾

画面：快速展示架构图或测试输出。

讲稿：

> 项目目前有 29 项后端测试，覆盖率 85%，并包含 7 项 Vitest 前端测试、Playwright 真实端到端测试、Docker Compose 和 GitHub Actions。所有性能数字都有脚本和原始样本可以复现。

## 简历项目描述参考

> 独立设计并实现本地代码仓库分析平台 DevAtlas，基于 FastAPI、React、SQLite 与 Tree-sitter 支持多来源仓库导入、跨语言结构解析、BM25 搜索、依赖图和六类质量检测；实现元数据快路径与 SHA-256 增量分析，在 9,553 行项目上将无变化重分析端到端中位耗时从 167.97 ms 降至 10.90 ms（15.41×），后端 29 项测试覆盖率 85%，并通过 Playwright 与 GitHub Actions 验证完整业务流程。

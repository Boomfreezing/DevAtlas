# 耦合分析：静态绑定与测试证据

日期：2026-09-12。本轮完善现有“耦合分析”，不新增产品菜单，不恢复全仓库函数调用图，不调用模型 API，不下载新模型或仓库，不推送 GitHub。

本文记录上一轮静态绑定实现与验收。后续真实源码抽查发现并修正的漏检、受哈希约束的原文补读及当前边界见[真实源码定向抽查](./COUPLING_REAL_EVALUATION.md)；下文“仅已有索引”的描述是上一轮实现范围。

## 原有问题与复现

旧实现把符号短名字作为字符串检索条件。例如选择 `alpha.save` 时，`beta.save()`、注释中的 `save()`、测试中只导入 `alpha` 的语句都可能进入直接调用者；导入别名又可能无法关联到正确目标。函数正文中的所有标识符也可能被当作被调用对象，而不是先确认调用表达式。

独立的小型 Python/TypeScript 源码回归在修改前为 **11 项失败、2 项通过**。保留项目隔离与文件级导入正例，避免通过清空结果“修复”误判。另外 6 项风险证据回归在旧实现全部失败：纯函数反例中，仅增加一个未证实的测试关联，就将同一基准风险从 21 降为 3。

这些是维护者构造的合成反例，不是独立真实仓库准确率基准，也不是运行时调用图精度评测。

## 关系语义

- **文件级关系**仍使用解析器已经定位的模块导入。导入一个文件，并不代表调用了其中每一个函数。
- **符号级直接调用者**要求真实调用语法、目标定义及可核验的静态绑定一致。只把文件导入了进来、文本提到同名函数，不再算作该符号的直接调用。
- **静态绑定调用**表示在已有源码索引中能定位绑定关系，并非运行时必然执行。入向关系的行号属于调用方文件；出向关系打开被调用对象的定义文件和定义行，不混用两个文件的行号。
- **调用候选**不能与已绑定调用混淆。缺失源码、截断、读取预算不足或无法确定作用域时，只能保守保留候选或省略，不能给出高置信结论。
- **二级影响**仍是模块层面的潜在回归范围；符号分析从已确认直接调用文件扩展，不从所有导入目标模块的文件扩展。接口与数据库实体列表仍主要依据路径线索，不能等同于完整业务链或 SQL 数据流。

前端沿用原有绿色 Terminal 布局：只调整关系标签与“相关测试候选”标题，不展示新的权重变量或新增区域。旧后端返回的文字匹配关系也明确标注为候选。点击入向调用优先定位其具体调用行，点击出向对象定位被调用文件的定义行；集成回归分别检查文件与高亮行，避免只在组件中验证回调参数。

## 风险中的测试证据

风险模型版本改为 `evidence_v3`，基准分及其他结构风险项保留。

原来的 `test_coverage` 是测试文件数量与关联模块数量之比，不是实际测试覆盖率，现改为 `test_evidence`（静态测试关联，单位为文件个数）：

- 只计入存在目标静态绑定调用的测试文件，按文件去重。
- 模块导入、二级关联、纯文本命中、低置信候选均不能获得这项减分。
- 少量测试关联只提供有限参考；减分有上限，不因不断增加测试文件而把风险压到零。
- 推荐先检查测试断言并实际运行。没有定位到目标测试，不等于项目没有测试；定位到了也不代表测试通过、分支覆盖或业务正确。

对文件级分析，相关测试仍可作为模块关联候选展示，但单纯导入不会被当作目标测试覆盖。不同评分模型的分数不宜直接当作代码改进幅度。

## 验证结果

- 后端全量 **378 项通过**，行覆盖率 **86.56%**，Ruff 通过；资源泄漏相关警告作为错误检查。
- 前端全量 **340 项通过**，25 个测试文件；TypeScript 检查及生产构建通过。
- Playwright **42 项通过**，包含真实隔离导入主流程与模拟 API 的交互回归；耦合关系用例已使用新 `bound_symbol_call`，验证从搜索进入分析、打开调用者并高亮具体第 17 行。
- 修改文档的相对链接、`git diff --check` 检查通过。

测试异常与处理也予以保留：首次默认并发单测暴露旧搜索测试仅等待标题、未等待项目工作区就绪的问题，补充 `aria-busy=false` 同步断言；后一次高并发运行中既有大目录用例超过原 5 秒超时，最终全量使用 `--maxWorkers=2` 通过，没有延长超时或降低断言。第一次浏览器测试全部执行通过后，沙箱中的子服务收尾阻塞；仅清理已核验的 8011/5175 测试进程后结束，再以能正常管理子进程的权限完整复跑，42 项通过并正常退出。

后端保留 1 条第三方 Starlette/httpx 弃用警告，本轮没有变更依赖。上述测试不能证明所有真实仓库无误报，也不能代替实际测试覆盖率或运行时调用验证。

测试数据、源码副本与临时目录均使用 D 盘隔离路径；未修改日常项目数据库、未重启日常服务，也未调用生成模型 API。若日常后端没有启用自动重载，需要重启后端以使用新逻辑。

## 范围与后续

该方案按需读取已有索引，不执行被分析代码；不会对所有函数建立持久调用图。分析结果针对当前索引，源码改变后仍应执行已有增量/全量分析。

符号入向与出向解析共享一次请求预算：最多读取 48 个文件、16 MiB 索引正文，每文件不超过 2 MiB、240 个索引片段；每方向最多返回 24 项关系。每文件遍历最多 60,000 个语法节点、保留最多 2,048 个调用位置。读取正文使用 SQL 字符/字节双限制；索引在两次读取间变化、缺行、截断、语法错误和递归过深均不产生高置信绑定。以上限制属于符号源码核验阶段，不等同于整个依赖快照的内存或响应时延保证。

超出预算时可能漏掉实际调用。片段不完整时，仅允许同文件低置信候选，不从缺少作用域上下文的片段推断跨文件调用。结果有上限，也不能把“已找到数量”当作全仓库真实调用总量。

动态接收者、反射、重新导出、星号导入等无法可靠绑定时保持保守；不能将“没有找到”描述成“没有关系”。后续应扩充带预期调用位置的真实样例，并分别衡量误关联和漏关联；不要通过重新启用无限制扫描来增加召回。

本轮不修改智能问答检索，也不重新运行 60 题模型检索对照。上一轮结果及其实现指纹保留在[离线检索复测报告](./QA_RECHECK.md)，不是本轮耦合分析精度证明。

# DevAtlas 项目推进计划

## 1. 项目目标

构建一个可以导入代码仓库、解析代码结构、搜索代码、展示依赖关系并检测质量问题的本地分析平台。项目应具备真实测试数据、清晰架构和一键启动能力，可作为后端、全栈或 AI 应用方向的简历项目。

M0～M5 保留既有建设里程碑，不是待重做的任务列表。当前测试数量、覆盖率及验收范围统一见 [根 README](../README.md#可量化结果)；以下计划不将历史测量改写成当前结果。新增模块、分析能力、外部下载或真实模型调用前，先与用户确认范围。

## 2. 核心架构

```text
ZIP / 本地文件夹 / 公开 GitHub 仓库
  → 上传与安全校验
  → 文件扫描和语言识别
  → Tree-sitter 结构解析
  → SQLite 结构化数据
  → BM25 与问答用的有界本地向量索引
  → 搜索、模块依赖图、耦合分析、质量与版本对比
  → 本地规则报告 / 用户配置生成模型后的报告与智能问答
```

| 模块 | 技术 |
|---|---|
| 前端 | React、TypeScript、Vite |
| 后端 | Python、FastAPI |
| 关系数据 | SQLite、SQLAlchemy |
| 代码解析 | Tree-sitter |
| 关键词检索 | BM25 |
| 语义检索 | 本地 ONNX Embedding 与有界向量索引；当前未使用 FAISS |
| 可视化 | React 与交互式 SVG；当前未使用 React Flow 或 ECharts |
| 测试 | Pytest、Vitest、Playwright |
| 交付 | Docker Compose、GitHub Actions |

本地规则引擎可直接生成报告，但不承担智能问答。问答必须接入用户配置的生成模型；本地嵌入模型只负责检索，不是免费的默认聊天模型，也不代表无需准备模型文件或运行资源。

## 4. 现状与后续优先级

- 已实现的功能基线：多来源导入、Python/TS/JS 结构解析、BM25、模块依赖图、按需耦合分析、质量规则、问答混合检索、后台任务、增量分析、报告、版本对比与远程同步。
- 最初评估提出的顺序保留在 [项目评估基线](./PROJECT_REVIEW_2026-09-12.md)，后续结果按下面的专题记录查阅，不能把最初问题列表当作当前未修复清单。
- 第一阶段进展：保留 3 个合成样例、36 道检索回归；后续新增 Flask/Requests/Express 固定版本真实源码、60 道题与仓库级划分，运行词法/结构/语义对照，修复长函数证据截断、追问路径硬约束和启动命令识别。真实生成回答、独立人工复核仍待完成，详见 [真实仓库评测](./QA_REAL_EVALUATION.md)，不把检索通过率写成回答准确率。
- 第二阶段进展：完成过期请求隔离、缓存失效期间旧计算回填保护、后台任务期间删除校验、快照分析口径记录与中性对比；新增独立浏览器回归。单实例可靠性及剩余并发边界见 [第二阶段验证](./STATE_CONSISTENCY.md)。
- 第三阶段进展：建立 24/240/1,200 文件合成性能基线，修复深依赖递归崩溃；拆分版本对比页面并取消过期读取。已保留接口及浏览器原始样本，不声称整体提速；真实样本、多批次首屏与其他页面拆分仍待继续，详见 [第三阶段记录](./WORKSPACE_PERFORMANCE.md)。
- 后续已分别打磨文件树、依赖图、质量页面、后台同步与问答会话，分主题入口见 [文档导航](./README.md)，不将这些独立样本混成一次全站性能提升。
- 耦合分析已区分可核验静态调用与候选，补齐 CommonJS、遮蔽和索引缺段的保守处理；真实定向抽查及哈希约束原文补读见 [耦合证据](./COUPLING_EVIDENCE.md) 和 [真实探针复测](./COUPLING_REAL_EVALUATION.md)。不是全仓库运行时调用图，也不据此声称零误报。

接下来按以下顺序推进已有功能，不新增菜单：

| 优先级 | 工作内容 | 完成条件 |
|---|---|---|
| 1. 稳定交付基线 | 修正已确认缺陷，保持既有安全边界和失败回归，整理文档及提交范围 | 当前代码的 lint、测试、构建和适用的隔离 E2E 有明确记录；按 [交付清单](./DELIVERY.md) 审查后推送，历史指标不重写 |
| 2. 复核关联与证据 | 请独立复核者检查已有耦合标注和问答证据，先整理误关联、漏关联及未覆盖场景 | 区分定向诊断样本与独立验收；新增真实语料或扩大范围需先确认，先冻结标注再运行，不按结果反改答案 |
| 3. 性能与维护性 | 在既有文件树、图谱、质量和项目切换场景做重复、负载可比的复测，再拆分热点实现 | 同时记录冷热缓存、构建模式、样本和回退；接口耗时、JS 堆与页面耗时分开，功能及定位契约不退化 |

生成回答及实际多轮质量仍需另行选择模型、确认数据外发与费用后验收；未授权时仅继续本地回归与已有功能打磨。用户系统、数据库/队列替换、新语言、完整调用图或团队规则属于扩展方向，不因出现在计划中而自动实施。

### 评测准备边界

- 常规 CI 使用已有合成样例与模拟模型请求，不自动下载真实仓库或模型，不调用真实生成服务；依赖和浏览器安装仍可能联网。
- 真实检索和耦合评测需要用户显式准备固定的本地 corpus，再校验源码锁后运行；不能假定普通克隆已包含第三方源码。
- 语义对照需要已有本地嵌入模型目录；真实生成验收另需生成服务，两者不可混淆。具体命令见 [交付清单](./DELIVERY.md#额外评测先准备再显式运行) 与对应专题文档。
- 不执行被分析仓库代码，不读写日常项目数据库，不把临时源码、模型缓存与原始运行目录提交到 Git。

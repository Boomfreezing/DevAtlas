# DevAtlas 项目推进计划

## 1. 项目目标

构建一个可以导入代码仓库、解析代码结构、搜索代码、展示依赖关系并检测质量问题的本地分析平台。项目应具备真实测试数据、清晰架构和一键启动能力，可作为后端、全栈或 AI 应用方向的简历项目。

## 2. 核心架构

```text
ZIP 仓库
  → 上传与安全校验
  → 文件扫描和语言识别
  → Tree-sitter 结构解析
  → SQLite 结构化数据
  → BM25 / FAISS 检索索引
  → 依赖图、搜索和质量报告
```

| 模块 | 技术 |
|---|---|
| 前端 | React、TypeScript、Vite |
| 后端 | Python、FastAPI |
| 关系数据 | SQLite、SQLAlchemy |
| 代码解析 | Tree-sitter |
| 关键词检索 | BM25 |
| 语义检索 | 本地 Embedding、FAISS |
| 可视化 | React Flow 或 ECharts |
| 测试 | Pytest、Vitest、Playwright |
| 交付 | Docker Compose、GitHub Actions |

## 3. 阶段与验收标准

### M0：工程初始化

- [x] 建立前后端目录
- [x] 提供健康检查接口
- [x] 建立 SQLite 数据库
- [x] 提供本地和 Docker 启动方式

验收：前后端可以独立构建，`/api/health` 返回 `{"status":"ok"}`。

### M1：仓库导入和扫描

- [x] 上传 ZIP 文件
- [x] 文件类型、大小和路径安全检查
- [x] 忽略依赖与构建目录
- [x] 统计文件、语言和代码行
- [x] 项目列表、详情和删除页面
- [x] 本地文件夹和公开 GitHub 仓库导入
- [x] 后端单元及接口测试

验收：用户可以完成一次真实仓库的导入、查看和删除。

### M2：代码结构解析

- [x] 集成 Tree-sitter
- [x] 支持 Python、TypeScript 和 JavaScript
- [x] 提取函数、类、接口、方法、导入和行号
- [x] 建立符号、导入关系和解析问题数据表
- [x] 为语法错误、超大文件和无法读取的文件提供容错

验收：测试仓库中的符号和导入关系能够被稳定提取并查询。

### M3：代码搜索

- [x] 按函数和类切分代码片段
- [x] 建立 BM25 索引
- [x] 返回路径、行号、代码片段和得分
- [x] 前端项目内代码搜索与结果展示
- [ ] 接入本地 Embedding 与 FAISS
- [ ] 实现关键词与向量混合排序

验收：建立至少 30 条人工查询，记录 Precision@5、Recall@5、MRR 和响应时间。

### M4：依赖可视化和质量检测

- [x] 输出模块依赖图 API
- [x] 前端支持缩放、筛选和节点详情
- [x] 检测循环依赖
- [x] 实现超长函数、超大文件等至少 5 条规则
- [x] 每条规则包含定位、说明和测试

验收：可以通过图形定位模块关系，并生成结构化质量报告。

### M5：工程化和交付

- [x] 后台分析任务和进度
- [x] 文件哈希增量分析
- [x] GitHub Actions
- [x] 端到端测试
- [x] 性能评测报告
- [x] 系统架构图和可复现项目截图
- [x] 2～3 分钟演示脚本
- [ ] 录制 2～3 分钟演示视频

验收：新用户按照 README 可以一键启动；简历中的所有数字均能在评测报告中复现。

## 4. 优先级

- P0：仓库上传、扫描、Python 结构解析、BM25、依赖图、基础质量规则。
- P1：TypeScript 解析、向量搜索、异步任务、增量分析、报告导出。
- P2：用户系统、PostgreSQL、Redis/Celery、GitHub 在线导入。

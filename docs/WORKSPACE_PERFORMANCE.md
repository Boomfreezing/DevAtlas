# 第三阶段：性能基线与页面维护性

验证日期：2026-09-12。沿用已有功能，不新增产品菜单、不升级依赖、不调用在线模型、不推送 GitHub。

## 1. 本轮实际修复

### 深层依赖导致分析失败

新增隔离样本首先发现：1,200 个文件组成较深的依赖环时，原递归版 Tarjan 遍历触发 `RecursionError`。异常从循环检测传递到质量报告与导入快照，导致导入失败。这不是上传大小限制或网络失败。

将遍历调用栈替换为显式 DFS 帧，保留强连通分量和自环识别、排序及现有接口，不提高 Python 递归上限。修复后该样本可以完成导入及所有基准请求。新增验证包括：

- 5,000 节点无环长链和闭合长环；
- 多个不相连的环、自环、单向跨分量边与空图；
- 80 个确定性随机小图，与独立的可达性算法逐一对照。

5,000 节点是循环检测单元测试规模，不是 5,000 文件端到端导入性能承诺。修复前大型样本未成功完成，因此没有可比较的修复前大型耗时，更不能计算“提速倍数”。

### 拆分现有版本对比页面

将版本对比、Git 对比及快照结果展示从 `App.tsx` 移至 `src/workspaces/SnapshotWorkspace.tsx`。入口、DOM 类名、按钮和绿色 Terminal 样式保持不变，没有新增菜单。

`App.tsx` 从本轮开始时的 3,248 行降至 2,910 行；这只是职责拆分，不是删除业务功能或减少同等数量的总代码。日期、数字与任务状态格式化提取到 `displayFormat.ts`，复用 `Intl` 格式化实例，测试验证原有输出不变。

`readRequests.ts` 为读取请求提供可复用的“同类最新请求优先”管理：

- 切换快照或 Git 对比条件时，中止旧读取并允许立即发起新对比，不等待旧服务端返回；
- 离开页面时取消列表、Git 摘要、对比和进度读取；
- 保存后刷新列表也经过同一请求管理，避免初始列表的晚到响应覆盖新列表；
- API 层保留取消异常，不再把主动取消显示为“后端无法连接”；
- 服务端可能已开始计算，因此仍保留过期响应校验；浏览器取消不保证后端计算停止。

保存、删除快照和提交远程同步是写操作，不通过此管理器取消。已提交任务继续在后台运行；页面卸载后不会再发起该页面的后续刷新。

## 2. 可复现样本与测量口径

原始结果、环境、文件摘要、全部时间样本见 [workspace-2026-09-12.json](./performance/workspace-2026-09-12.json)。

三个 `orders-v1` 样本由固定脚本生成 Python 文件，含导入环、普通函数和超长函数。每份样本记录内容摘要，ZIP 只包含合成源码。它们用于发现规模与深度问题，不代表真实 Python/TS/JS 混合仓库，更不是用户已导入的项目。

| 档位 | 文件数 | 源码行数 |
| --- | ---: | ---: |
| small | 24 | 972 |
| medium | 240 | 9,360 |
| large | 1,200 | 46,800 |

环境为 Windows 11、Python 3.13.5。后端使用独立 SQLite 和 `TestClient`，覆盖路由、查询、业务计算、验证与响应序列化，但不含真实网络套接字、Vite 或浏览器渲染。

每种后端场景采样 20 次；P50/P95 使用 nearest-rank。`cold` 仅指每次请求前清空进程内分析/搜索缓存，不清除操作系统磁盘缓存，也不是冷启动新进程。`warm` 先预热再采样。搜索为固定宽泛关键词 `order validation`，不代表所有查询。

使用真实隔离的后端 `8011`、Vite 开发服务 `5175`、本机 Chrome、1440×1000 视口。每个动作采样 10 次，P95 因此是该批次最大值。计时包含自动化点击/等待以及两帧绘制等待，不是精确的用户输入延迟或生产构建性能。

## 3. 复现命令

在根目录使用 PowerShell，所有运行文件位于项目所在磁盘的 `data/tmp`：

```powershell
$env:TEMP = Join-Path (Get-Location) 'data/tmp'
$env:TMP = $env:TEMP
New-Item -ItemType Directory -Force -Path $env:TEMP | Out-Null
Push-Location backend
.\.venv\Scripts\python.exe -m evaluations.workspace_performance --samples 20
Pop-Location
```

命令最后打印该轮的 `result.json` 绝对路径，将它填入下面的变量；不要使用用户仓库的路径：

```powershell
$env:DEVATLAS_PERF_CORPUS = '上一步输出的 result.json 绝对路径'
Push-Location frontend
npm run test:e2e -- --config=playwright.performance.config.ts
Pop-Location
```

浏览器测试会把同一批合成 ZIP 导入全新的独立数据库，打印 `browser-performance.json` 的位置，结束后回收测试服务。它不访问真实 GitHub、模型、日常数据库或 `8000/5173` 服务。需要本机可用的 Playwright/Chrome 及启动、回收进程的权限。性能脚本为显式执行，不增加普通 CI 的每次运行成本。

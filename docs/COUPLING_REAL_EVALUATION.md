# 耦合分析：真实源码定向抽查

日期：2026-09-12。完善现有耦合分析，不增加产品入口，不恢复全仓库函数调用图，不调用生成模型或下载新源码，不推送 GitHub。

## 样本与方法

复用已保存在本地的 Flask 3.1.0、Requests 2.32.3、Express 4.21.2 源码。版本、Commit、归档 SHA256 及许可证沿用[已有源码锁](../benchmarks/repository_qa_real/repositories.json)；每次运行验证全部文件指纹，不执行样本项目代码。

先阅读源码、编写并冻结 24 条探针，再运行分析器。每个项目 8 条，其中 5 条应确认关系、3 条不应高置信确认的关系。标注包含目标文件、符号定义锚点、调用或定义位置与判断理由，前后两次使用完全相同的源码和标注。

这里的“反例”既包括同名但不同目标，也包括无法证明静态绑定的动态接收者、回调注册与纯导入；不声称这些地方运行时绝不发生调用。

这是维护者编写的定向诊断样本，没有独立外部复核，也不是新的独立留出集。它只检查指定文件/行号对上的关系，不穷举全部正确调用，**不能换算为整个调用图的 precision、recall 或仓库级准确率**。修复参考了这些失败样例，因此复测结果属于回归验证。

## 发现与修复

### 1. 搜索分块不是完整源码

现有搜索索引对类只保留有限头部，再单独索引方法。Flask `app.py` 的 118–222 行、`wrappers.py` 的 55–56 行没有完整进入搜索片段；直接拼片段会丢失类作用域，旧解析器因此拒绝高置信关系。

未调整问答分块或填造空白行。现在仅在索引缺行时尝试补读已导入的本地原文，要求：

- 文件路径解析后仍位于该项目目录内。
- 原始字节 SHA256 与已分析的文件记录完全一致。
- 总行数与已有索引片段逐行一致。
- 单次原文大小不超过 2 MiB；额外 1 字节的超限探测也计入请求预算。
- 原有索引读取和补读共同受 48 文件、16 MiB 单次请求预算约束。索引正文每文件仍限 2 MiB，补读原文另限 2 MiB；这不是进程 RSS 上限。

完整索引不会触发磁盘补读；索引冲突、元数据漂移、源码已更改、缺少哈希、文件缺失、路径越界或超限时仍保守降级。该修复无需重建旧索引，不改变磁盘源码和问答索引。

### 2. 删除字典项不等于删除函数绑定

Requests 中的 `del os.environ[env_name]`、`del headers[key]` 曾使整个文件被标记为不可确认，连带漏掉无关的 `select_proxy`、`get_environ_proxies` 等调用。

现在区分简单下标项删除与名称/属性删除。后者仍保守处理；动态接收者不会因此变成可确认的函数调用。新增反例继续保护 `del save`、`del mod.save` 及混合删除。

### 3. CommonJS 构造器与原型属性

Express 的 `Route = require('./route')` 指向显式 `module.exports = Route`，但旧实现把模块引用一律视为不可直接调用。另有 `Route.prototype.method = ...` 和 `Route.prototype[method] = ...` 被误当作重新赋值 `Route`。

现在只对可核验的 CommonJS 默认导出允许函数调用和构造调用；不把 ES namespace 当作可调用函数。已知构造函数的原型成员赋值保留构造函数身份，但不据此解析动态方法。

新增防误关联回归覆盖导出被对象覆盖、计算属性覆盖、嵌套导出、局部 `module`/`require` 遮蔽、延迟写入、真正的构造函数重赋值。无法证明导出稳定时，不继续使用旧定义。

## 风险评分与后续

本轮保留 `evidence_v3` 风险公式和权重。新增识别的关系可能改变分数输入，但不是代码质量变差的证据。这里没有实际缺陷、变更失败或测试执行标签，不具备据此重新标定风险权重的依据；源码静态测试关联依然不等于覆盖率或测试通过。

下一步优先让独立复核者检查固定探针，并增加未参与本轮修复的真实样例，覆盖类型导入、重新导出、继承和动态调用等边界。先衡量误关联与漏关联，再决定扩大解析范围。若进一步调整风险评分，应先建立真实变更与验证结果的标注依据，不单凭希望分数更好看而修改权重。

## 本地复现

在后端目录使用项目虚拟环境运行：

```powershell
$env:TEMP = (Resolve-Path '../data/tmp').Path
$env:TMP = $env:TEMP
$env:DEVATLAS_DATABASE_URL = 'sqlite:///:memory:'
$env:HF_HUB_OFFLINE = '1'
$env:TRANSFORMERS_OFFLINE = '1'
$env:PYTHONUTF8 = '1'
.\.venv\Scripts\python.exe -m evaluations.coupling_real
```

默认只校验已有源码，不提供自动下载或模型调用选项。输出位于项目 `data/tmp/coupling-runs/run-*/evaluation/`，使用新的 SQLite 数据库与搜索索引，不修改日常数据库和运行服务。不覆盖先前结果；缺失或不唯一的目标不会让负例假通过。退出码 0 表示探针通过，1 表示存在失败探针，3 表示运行期间输入或实现漂移。

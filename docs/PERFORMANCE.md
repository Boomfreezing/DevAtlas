# DevAtlas 性能评测

## 1. 评测目标

验证文件哈希增量分析在仓库内容没有变化时，能否减少重复扫描、Tree-sitter 解析和索引构建的开销。报告中的全量与增量数据均采用同一客户端端到端计时口径，包括 HTTP 请求、服务端处理和响应传输。

## 2. 环境与方法

- 日期：2026-08-26
- 系统：Windows，本地开发模式
- 后端：Python 3.13、FastAPI、SQLite
- 测量工具：PowerShell `Stopwatch` + `Invoke-WebRequest`
- 全量接口：`POST /api/projects/{id}/reanalyze`
- 增量接口：`POST /api/projects/{id}/incremental-reanalyze`
- 增量场景：仓库文件未发生变化
- 汇总指标：多次请求的中位数；大型仓库全量分析仅运行一次，结果标注为单次样本

运行可复现脚本：

```powershell
.\scripts\benchmark_incremental.ps1 -ProjectId 3 -FullRuns 3 -IncrementalRuns 5
```

脚本输出项目规模、每次样本、平均值、中位数、最小值、最大值和中位数加速比。测试前需启动后端，并将 `ProjectId` 替换为本机已经导入的项目 ID。

## 3. 结果

### 3.1 中型项目

项目规模：26 个文件，9,553 行代码。

| 模式 | 样本（ms） | 中位数 | 平均值 |
|---|---:|---:|---:|
| 全量重新分析 | 167.97、153.27、171.05 | 167.97 ms | 164.10 ms |
| 无变化增量分析 | 10.51、10.90、10.73、11.26、12.00 | 10.90 ms | 11.08 ms |

中位数加速比：**15.41×**。

### 3.2 大型项目

项目规模：929 个文件，40,515 行代码。

| 模式 | 样本（ms） | 中位数 | 平均值 |
|---|---:|---:|---:|
| 全量重新分析 | 1,646.26 | 1,646.26 ms | 1,646.26 ms |
| 无变化增量分析 | 305.61、287.54、280.87 | 287.54 ms | 291.34 ms |

中位数加速比：**5.73×**。全量结果仅有一次样本，后续正式发布前应扩充到至少五次。

## 4. 结论

无变化增量分析能够跳过源文件内容读取、Tree-sitter 重解析和搜索索引重建。中型项目的主要收益来自跳过解析和索引；大型项目仍需遍历 929 个目录项并读取文件元数据，因此加速比低于中型项目，但端到端耗时保持在 300 ms 左右。

当前变更场景仍会重新构建整个 BM25 索引。后续可以将搜索索引改为按文件更新，并增加“少量文件变化”“冷启动”和不同磁盘环境的对照实验。

## 5. 数据使用边界

- 简历中建议写“无变化增量分析最高加速 15.4×”，并注明测试项目规模。
- 不应将服务端内部计时与客户端端到端计时直接相除。
- 所有结果均为当前本机样本，不代表云服务器或其他磁盘环境。
